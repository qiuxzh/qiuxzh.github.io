实验3：数据预处理

qiuxz2026-11-212026-11-21

实验三拿泰坦尼克号乘员表做一遍完整的数据预处理：从读入、查重复、补缺失开始，到连续量分箱、字符串编码、特征构造、缩放，最后用 PCA 降到三个主成分。

数据集是 Titanictrain.csv，891 行 12 列：

字段 含义
PassengerId 乘客编号
Survived 是否生还，0/1，也就是后面的目标向量
Pclass 船舱等级，1/2/3 等座
Name 姓名，格式是「姓, 称谓. 名」
Sex 性别
Age 年龄
SibSp 同船的兄弟姐妹、配偶数
Parch 同船的父母、子女数
Ticket 票号
Fare 票价
Cabin 客舱号
Embarked 登船码头，C/Q/S

环境是 Python 3.9 + Jupyter Notebook，pandas、numpy、matplotlib、scikit-learn。

1. 读入与认识数据

info() 有四个看点：891 entries 是行数，12 columns 是属性数，Non-Null Count 逐列给出非空个数，缺多少一眼就能算出来；Dtype 是类型，int64/float64 是数值，object 是字符串。类型决定了后面能做什么：数值列能算均值、能标准化，object 列只能编码。

用绝对路径的话有两种写法，一是把 \ 全部改成 \\，二是在字符串前加 r，路径原样粘贴即可：

2. 重复值

有 PassengerId 在，理论上不会有重复行，但仍然要查一遍：

subset 指定按哪一列判断重复，列名必须和数据集里完全一致，大小写敏感；inplace=True 是在原对象上直接删，不返回新表。这一点在 pandas 3.x 里已经改成推荐用重新赋值 df = df.drop_duplicates(...)，inplace 参数被标记为弃用，两种写法结果一样。

3. 缺失值

3.1 先统计，再画图

isnull() 返回一张 True/False 的表，True 当 1 参与求和，所以 .sum() 得到的就是每列缺失个数。结果三个字段有缺失：Cabin 687、Age 177、Embarked 2。

看个数还不够，占比才决定策略：

Cabin 缺 77%，Age 缺 19.9%，Embarked 缺 0.2%。三个量级对应三种处理办法。

3.2 Cabin：整列删掉

用剩下的 23% 去补 77%，补出来的值基本是编的，还会给模型引入噪声，不如直接删：

判断依据不是「能不能补」，而是「补完之后还有没有信息量」。

3.3 Age：看过分布再决定用哪个数填

箱线图上七十八十岁有几个点冒出来，那是离群点；但年龄对乘客本身是合理的，不是错误数据，所以不处理。直方图显示人数集中在十几到三十岁，分布明显右偏、不居中，这时候用均值会被高年龄段拉高，用中位数更稳：

3.4 Embarked：object 列用众数

码头是 C/Q/S 三个字符串，算不出平均值，只能用出现最多的那个：

mode() 返回的是一个 Series，可能有并列众数，所以后面要 [0] 取第一个，直接填会报错。这是本实验第一个反复出现的坑：返回列表/Series 的地方，要想清楚取哪一个。

4. 票价：偏态与对数变换

票价集中在十几块，尾巴一直拖到 500 多，偏度 4.79，是典型的重尾右偏。取对数把大值压下来：

用 log1p 而不是 log，是因为有票价为 0 的记录，log(0) 是负无穷。变换后偏度从 4.79 降到 0.39，接近对称。

想把变换前后放一张图对比，取值范围差太多，得开第二根纵轴：

5. 连续量分箱

30 岁和 31 岁、10.5 元和 10.8 元的票，对「活没活下来」这个判断几乎没有区别，把连续值切成少数几段反而更好用。切法有两种，取决于数据分布。

5.1 年龄：等距分箱 pd.cut

自己给切分点，按年龄区间切：

六段的人数分别是 30、34、75、447、283、22，18–30 岁这一段占了整整一半，说明按距离切在这个数据上并不均匀，但年龄段本身有业务含义（幼儿、学龄、青少年、青年、中年、老年），所以保留等距切法。

5.2 票价：等深分箱 pd.qcut

票价太集中，按距离切会出现某一段只有几条记录的情况，改成按分位数切，让每段人数尽量相等：

五段人数 179、184、172、180、176，接近均分（178.2）；retbins=True 顺便返回实际切分点，在 log 域是 0、2.18、2.44、3.12、3.71、6.24，折回原值大约是 0、7.85、10.50、21.66、39.87、512。

这里有个常被误解的点：先 log1p 再 qcut，和直接对原始 Fare 做 qcut(5)，结果完全一样。因为对数变换是单调的，分位数是保序的，切出来的边界只是换了个坐标表示。两种写法随便选一种，不必纠结。

6. 标签编码

前面切出来的 category、Fare_bin，加上 Sex、Embarked，全是字符串，模型吃不了，要转成数值。转法有两种：标签编码（label encoding）和独热编码（one-hot encoding），实验用的是前者。

标签编码是按字典序给类别编号 0、1、2……，实现简单，但隐含了「类别之间有序」的假设，对码头、称谓这种无序类别其实不完全合适，需要时改用 pd.get_dummies。

7. 从姓名里拆出称谓

Name 看着是无关字段，但里面藏着 Mr / Mrs / Miss / Master 这类称谓，而称谓和性别、年龄、舱位都强相关，是很好的特征。姓名格式是「姓, 称谓. 名」，切两次就出来了：

expand=True 把切分结果扩成多列，再用方括号取需要的那一列。value_counts() 出来是一长串：Mr 517、Miss 182、Mrs 125、Master 40，还有 Dr、Major、Sir、Lady、Don、Jonkheer 这些只出现一两次的。

稀少的称谓各自成一类没有统计意义，用字典映射把它们并成 Officer 和 Royalty：

归并后剩六类：Mr 517、Miss 185、Mrs 126、Master 40、Officer 18、Royalty 5。

字典里必须把 Mr / Mrs / Miss / Master 也写进去，哪怕映射到它们自己。map 查不到的键直接变成 NaN，如果只写稀有的那几个，517 个 Mr 会全部消失。这是第二个坑。

最后把它也编码：

8. 构造特征、抽取特征

SibSp 和 Parch 分开看是两个数，合起来才是「一家人有几个在船上」，而家庭规模很影响生还概率（互相照应，但人太多也难照顾）：

原始列（PassengerId、Name、Ticket）此时已经没用了，只留下编码后的列。把列名列表存成变量，是因为后面缩放完还要用它还原列名：

9. 特征缩放

data.describe() 先看量纲：Family 最大 11，fare_code 最大 4，Pclass 是 1–3，目标向量的尺度差得不多，但为了演示还是把三种缩放都做一遍，实际项目按需选一种。

三者的区别：MinMax 保留原始分布形状，只改区间，对离群值敏感；Standard 把每列拉到同一量纲，是大多数模型的默认选择；Normalizer 归一的是每一行，让每条样本的向量长度为 1，适合文本、稀疏特征，0 依然是 0。

fit_transform 返回的是 ndarray，行索引和列名都丢了，所以必须用 pd.DataFrame(temp, columns=reserve) 重新包一层——这也是前面要先存 reserve 的原因。直接把返回值当 DataFrame 用，后面 data_df['Family'] 会报 KeyError。第三个坑。

10. 相关分析与 PCA

10.1 协方差与相关系数

两个指标都是绝对值越大越相关，相关系数被限制在 [-1, 1]，协方差没有上下界、受量纲影响，所以看相关性强弱用相关系数。Family = SibSp + Parch，和 SibSp 高度相关是构造出来的必然结果，不算发现。

10.2 PCA 降到三个主成分

三个主成分分别解释 44.5%、19.5%、16.0% 的方差，累计 80%，原来 9 个特征压成 3 列还留住了大部分信息。参数名是 n_components，不是 k；Survived 如果不先 drop，它会被当成一个特征参与降维，标签就混进特征里了——这是第四个坑，而且它不会报错，只是结果悄悄变错。

降维结果是原特征的线性组合，不是从 9 列里挑 3 列，所以新列没有名字，只能叫 0、1、2，看载荷才知道每根主成分代表什么：

PC1 上 age_code 的载荷 0.906，基本就是「年龄段」这根轴；PC2 主要由 Family（0.675）撑起来；PC3 是 fare_code（0.880），也就是票价档位。三根轴刚好对应年龄、家庭、票价三个维度。
