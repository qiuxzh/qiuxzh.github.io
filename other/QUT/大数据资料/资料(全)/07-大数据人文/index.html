07 大数据人文

qiuxz2026-11-162026-11-16

一个数据项目，是一个程序员从头写到尾吗？

不是。项目要经过七个阶段，每个阶段的问题不同，需要的人也不同。

目标Target → 定义Define → 采集与管理Acquisition → 模型洞察Insight → 验证与优化Verify → 可视化与文档Visualize → 应用与维护Maintain

阶段 要回答什么
目标 target 这个项目要解决什么业务问题
定义 define 成功长什么样，用什么指标衡量
采集与管理 数据从哪来，怎么存，怎么保证可用
模型洞察 model insight 用模型从数据里拿到结论
验证与优化 结论在没见过的数据上还成立吗
可视化与文档 结论怎么表达给人看，过程怎么留档
应用与维护 上线之后谁盯着，模型失效了怎么办

七段里只有「模型洞察」是算法活。前后各段占的时间往往比建模本身更多，这一点在项目开始之前就得认下来，否则排期一定崩。

六种角色

角色 管什么
项目发起人
project sponsor		 项目的出资人，代表项目的最终利益
项目经理
project manager		 项目的实际管理者，管范围、时间、人力、成本、风险、质量、沟通、采购
客户
client		 项目的最终使用者，代表用户需求，有时兼任领域专家
数据科学家
data scientist		 负责数据管理策略，决定数据处理方式与技术方案，做数据产品的研发
数据工程师
data engineer		 把数据科学家提出的方法与技术方案，落到具体的软件与硬件上
运维
operators		 负责系统与基础设施的管理和维护

最容易混的是中间两个。数据科学家定「做什么、用什么方法」，数据工程师把它变成「能跑起来的东西」。 一个偏方案，一个偏实现。项目小的时候一个人兼两角，但这两件事的性质完全不同，混着做往往两头都不到位。

产业链的几层

层 内容
数据来源 data sources 数据从哪产生、从哪采集
大数据基础设施 存储与计算的底座
大数据分析 处理与建模
大数据应用 行业落地
开源项目 上面几层大量依赖的开源生态
就业方向 由上面几层衍生出的岗位

六项里开源项目与就业方向是横切面：每一层都有对应的开源组件，也都有对应的岗位。

总结

  1. 七阶段：目标、定义、采集与管理、模型洞察、验证与优化、可视化与文档、应用与维护。
  2. 六角色：项目发起人、项目经理、客户、数据科学家、数据工程师、运维。
  3. 分界：数据科学家定方案，数据工程师做实现。
  4. 产业链：数据来源、基础设施、分析、应用；开源项目与就业方向是横切面。

7.2　安全与隐私不是一回事

「保护好用户隐私」和「保证数据安全」，是同一件事吗？

不是。两个词经常一起出现，落点却不同，混着用会把责任也搅混。

概念 定义 关键词
隐私
privacy		 当事人不愿意被他人知道、或他人不便知道的敏感信息；与公共利益、群体利益无关 隐藏
安全
security		 不受威胁，没有危险、危害、损失 不受侵害

差别在于「被谁、以什么方式碰到」。安全讲的是数据有没有被非授权地拿走或破坏，隐私讲的是数据里属于个人的那一部分能不能被别人知道。 一份数据可以很安全（存得住、没人偷走），同时很不讲隐私（合法地把用户的家庭住址拿去分析）。反过来，一份把个人信息全部删掉的数据，隐私上是干净的，但被攻击导致丢失照样是安全问题。

三类现实中的出事方式

类型 说明
数据泄露 data breach 数据被非授权地传播出去
网络安全攻击 cybersecurity attack 外部主动入侵
内部人员误操作
accidental action by internal personnel		 不是恶意，但越权访问或错发了数据

第三类常被低估。前两类可以靠边界防护挡住，第三类发生在边界内部，防火墙帮不上忙。

为什么这件事的分量在变重

数据被称为新时代的「黄金」或「石油」，正在成为企业的核心资产、创新的关键来源、国家的战略资源。位置一变，风险的性质就变了。

  1. 大数据安全是保障企业、国家与社会安全的 重要基础；
  2. 它涉及国家安全、社会利益与企业核心资产；
  3. 它是企业实现可持续发展的关键因素之一。

三条说的都不是「丢几行数据」这种量级。数据丢失与个人信息泄露事件频发，地下数据交易造成数据滥用与网络诈骗，从关键基础设施的数据、特定行业的生产数据里还能分析出国家的重要战略情报，甚至危害国家安全。数据集中到哪里，风险就集中到哪里。

总结

  1. 隐私：当事人不愿被他人知道的敏感信息，与公共利益、群体利益无关，特点是隐藏。
  2. 安全：不受威胁、没有危险危害损失。
  3. 不等于：安全管「有没有被非授权拿走」，隐私管「能不能被知道」。
  4. 三类事件：数据泄露、网络攻击、内部人员误操作。
  5. 分量：涉及国家安全、社会利益、企业核心资产，也是可持续发展的关键因素。

7.3　大数据安全面对的六个挑战

大数据把安全变难了还是变简单了？

变难了，而且是从六个方向同时变难。每一条都能追到数据本身的某个特征上。

挑战 为什么
数据被滥用、误用、窃取 三种情形性质不同，见下
体量大，更容易成为攻击目标 数据集中在一处，攻破一次的收益极大
类型多样，有效性校验的工作剧增 结构化与非结构化混在一起，区分有用与无用越来越难
价值密度低，防御边界被撑大 要从海量数据里筛出少量有用信息，安全管理的范围跟着放大
处理快，对安全提出高性能要求 数据流得快，防护手段慢一步就等于没有
网络相对开放，加固策略效果下降 数据集可以无限延伸，网络必须更开放，防护就难做

第一条里的三个词要先分清，它们的责任方完全不同。

词 意思 边界在哪
滥用
abuse		 对数据的使用超出了预先约定的场景与目的 用途层面，不是访问权限层面
误用
misuse		 在正常范围内处理数据的过程中，泄露了个人敏感信息 处理过程中，不是故意的
窃取
theft		 数据被非授权地拿走 与系统安全关系最大

滥用最麻烦的地方在于它的理想方案做不到。理想情况下，每一条个人信息、每一个员工、每一个工作场景下的请求，都应该单独授权。但大数据业务里这个数量级根本批不完，只能按类授权，滥用就是从这里开始的。很多企业也确实还缺技术能力或安全意识，避免不了数据在分析处理的过程中泄露隐私。窃取这一侧的问题则偏向另一个方向：很多企业只重视对外部入侵的防御，忽视了内部入侵。

数据的使用者同时也是数据的创造者和供给者，数据之间的联系可以持续扩展，数据集可以无限延伸，这些都要求数据网络更开放。而网络越开放，加固策略越难见效。安全与开放在这里是直接冲突的，不是能同时最优的两件事。

挑战、滥用、开放

① 六个挑战各自能追到体量大、类型多、密度低、速度快、网络开放这几个特征上；
② 滥用是用超了范围，误用是处理过程中泄了，窃取是被拿走，三者责任方不同；
③ 安全与开放直接冲突，不可能同时最优。

总结

  1. 六个挑战：滥用误用窃取、体量大易被盯、类型多校验难、密度低边界大、速度快要求高、网络开放加固失效。
  2. 三个词：滥用超出约定场景，误用处理中泄露，窃取被非授权拿走。
  3. 难点：按条授权做不到，只能按类授权；内部入侵常被忽视；安全与开放互相牵制。

7.4　数据伦理：技术之外的对错

合法的事，是不是就等于该做的事？

不等于。法律划的是下限，伦理管的是法律还没管到的部分。数据伦理（data ethics）指的是在使用、处理、分析与共享大数据时应当遵守的道德与伦理原则。四条。

原则 要求
尊重隐私
respect for privacy		 保护个人隐私，保证数据的安全与机密
公平公正
fairness and justice		 保证数据及其使用是公平公正的，避免歧视与不公
透明可解释
transparency and interpretability		 数据的收集、处理、使用应当透明，可解释、可追溯
责任
responsibility		 对数据的误用与滥用负责，采取措施预防并纠正不良影响

四条里最容易被漏掉的是第二条。模型不会自己歧视，但它会把训练数据里的偏见学下来再放大：用历史上某个岗位的招聘数据训练筛选模型，如果历史上某个群体录用得少，模型就会继续少录。算法本身是中立的，训练数据不是。

四家有名字的做法

公司 做法 对应哪条原则
Google 调整搜索算法，降低不准确信息的排名，减少假新闻传播 责任
Microsoft 建立负责任人工智能计划，保证 AI 的开发与使用符合伦理标准 责任、透明
Amazon 推出透明度计划，公开数据收集与处理方式 透明可解释
Apple 采取一系列隐私保护措施，保证用户数据的安全与隐私 尊重隐私

四件事的共同点是：它们在技术上都做得到，主动给自己加了约束。 伦理落到执行层面，多数就是这种自愿的自我限制。

总结

  1. 定义：使用、处理、分析、共享大数据时应遵守的道德与伦理原则。
  2. 四条原则：尊重隐私、公平公正、透明可解释、责任。
  3. 陷阱：算法中立，训练数据不中立，偏见会被学下来并放大。
  4. 形态：伦理多表现为自愿的自我约束，而不是技术做不到。

7.5　隐私与大数据的反向关系

大数据越强，隐私一定越少吗？

在信息不对称这个维度上，两者的方向确实相反。隐私让个人对自己的数据保留信息不对称；大数据让组织减少既有的信息不对称。一个在收，一个在放。

换个说法：隐私是一组权利，用来限制别人知道关于你的某些事实；大数据是一种能力，让别人知道你更多。 两者作用在同一批信息上，方向相反，所以天然对立。这组对立是结构性的，不是谁对谁错的问题。

规则总是跟不上技术

规则是有的，问题在于它滞后于技术。围绕「大数据时代怎么保护隐私」，有四条建议。

建议 为什么
规则应当管数据的用途，而不是管分析过程 分析手段不断翻新，用途相对稳定，也更容易落成条文
规则不该把技术方案写进去，只写想要的结果 写死具体技术，技术一换代条文就作废
法律层面与社会机制都要有 光有法条不够，还需要执行与监督的机制
教育与培训要跟上，技术行业应引入数字隐私专家 隐私不是一个部门的事，要进到开发与管理流程里

前两条是一组：把规则写在「目的」上，不要写在「手段」上。 写在手段上的规则，会被技术进步一条条绕过去。后两条也是一组：一条落在制度，一条落在人。

国内的相关立法

关于个人信息保护，长期的状态是分散立法：没有一部专门的个人信息保护法，相关规定散见在多部法律法规与规章制度里。据统计，涉及个人信息与隐私保护的有近四十部法律、三十余部法规、近二百部规章。

同时顶层立法在逐步加强：《网络安全法》《刑法》《民法》等基本法里陆续加入了个人信息保护的内容，法律体系在逐步完善。

这段描述对应的是较早的一个时间点。2021 年 11 月 1 日，《中华人民共和国个人信息保护法》正式施行，专门立法这一环补上了，此前的「分散立法 + 顶层加强」变成了「专门法为主、多法并行」。把前后两个阶段连起来看，能看出一条明确的线：从散在多部法里，到立一部专门法。

总结

  1. 反向：隐私要保留信息不对称，大数据要减少信息不对称，两者在同一批信息上方向相反。
  2. 滞后：规则跟不上技术，是这对矛盾长期存在的原因。
  3. 四条建议：管用途不管过程、写结果不写技术、法律与社会机制并行、教育与培训加数字隐私专家。
  4. 立法路径：先分散在多部法律法规里，逐步在《网络安全法》《刑法》《民法》中加强，2021 年出台专门法。

7.6　数据治理：把数据当资产管理

模型建得很漂亮，放到真实数据上却没有效果，问题出在哪？

多数时候出在数据本身，不在模型。数据治理（data governance）管的就是这件事：保证数据的正确性与高质量，让模型拿到的原料靠得住。

2015 年，我国发布了《数据治理白皮书》国家标准研究报告，在其中提出了数据治理框架模型。它是广义信息治理计划的一部分，也就是制定与大数据有关的数据优化、隐私保护与数据变现的政策。

人、过程、技术

数据治理是一个体系，不是一套工具。它把三样东西按规范组织起来，对数据进行一系列管理，实现过程管控。

人People + 过程Process + 技术Technology → 规范化的数据管护governance

三项里最常被漏掉的是「人」。买一套数据管理平台不等于做了治理：没有明确谁负责、按什么流程（procedure）做，工具只是一个空壳。

要保证的四件事

治理的目标可以概括成一句：让数据作为一种资产（business asset）被正确地对待，为业务目标（business objective）服务。

要求 英文 意思
保护 protection 不被非法访问与破坏
适当的管理和使用 proper use and management 用在该用的地方，用得对
共享 share 需要的人能拿到
服务业务目标 business objective 前三件事不是为了合规而合规

第三件与第一件是一对张力：数据越保护越难共享，越共享越难保护。治理要做的是把规则定下来，不是选一头：什么数据、给谁、在什么条件下、可以做什么动作。规则定得下来，保护和共享才能同时成立。

把整条技术链连起来

回头看整门课的骨架，是一条链：每一环都有对应的技术，也都有对应的风险与制度问题。

环节 技术 风险 / 制度
产生 传感器、日志、交易记录 采集是否合规
采集 爬虫、Robots 协议、ETL 越权抓取、数据滥用
存储 HDFS、NoSQL、HBase 泄露、被攻击
预处理 清洗、集成、变换、归约 处理中误用、脱敏不彻底
分析 可视化、机器学习、模型评估 偏见被放大、结论不可解释
落地 应用与维护 责任不清、治理缺位

两列的性质完全不同。左边一列是技术问题，加机器、换算法、调参数都可能解决；右边一列不是，它涉及谁有权、谁负责、按什么规则办。越往右，越难靠算力解决。

治理是什么

① 数据治理是体系，不是工具：人 + 过程 + 技术；
② 目标是让数据作为资产被保护、被恰当使用与管理、被共享，并服务业务目标；
③ 保护与共享是一对张力，靠把规则定下来化解，而不是二选一。

总结

  1. 由来：2015 年《数据治理白皮书》提出数据治理框架模型；是广义信息治理计划的一部分。
  2. 定义：集中人（People）、过程（Process）、技术（Technology）的规范化数据管护过程。
  3. 四件事：保护、适当的管理和使用、共享、服务业务目标。
  4. 张力：保护与共享互相牵制，靠规则而不是靠取舍。
  5. 全链：产生、采集、存储、预处理、分析、落地；越往后越不是技术能解决的。
