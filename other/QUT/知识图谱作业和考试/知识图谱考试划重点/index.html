第一部分 全景：构建方法、发展阶段、分类、技术内涵

§1 知识图谱的构建方法

考点：自顶向下、自底向上、混合三种，各自适用什么场景。

答法一（一句话）

知识图谱的构建分自顶向下与自底向上两条路线：前者先定本体再填数据，后者先从数据里抽实体关系再归纳出模式；工程上多用两者结合的混合法。

答法二（标准版：按三层答）

  1. 自顶向下（Top-down）：从预定义的本体（Ontology）出发，先确定概念层次、关系类型与约束，再把实体按这个骨架填入。数据表示结构化、受控，适合企业知识管理、医疗报告、金融服务、政府公共管理、科学研究这类领域边界清楚、schema 相对稳定的场景。优点是结构规范、一致性好、便于推理；缺点是本体的设计与维护成本高，遇到新概念要先改本体。
  2. 自底向上（Bottom-up）：实体与关系从结构化元数据、非结构化与半结构化数据、众包数据中抽取出来，抽取后再逐步聚类、归纳、抽象成模式。模式（本体）是基于数据开发的，随新实体类型与新关系的发现逐步创建。优点是覆盖面广、能跟上数据变化；缺点是质量参差、模式层不一致、需要额外的对齐与清洗。
  3. 混合法：先自上而下搭骨架，再自下而上填充与扩展。智慧农业、智慧消防两个案例都采用混合构建法：纯自顶向下覆盖不了领域实体的复杂性，纯自底向上保不住数据质量与完整性。

答法三（展开，给论述题用）

构建方法的选择取决于三件事：领域边界是否清楚、schema 是否稳定、数据量级与变化速度。

  • 领域封闭、术语有国家标准（医疗、金融监管）→ 自顶向下。国家药典、ICD 编码这类本体已经是现成的骨架，再自底向上会重复造轮子。
  • 领域开放、每天冒新词（互联网内容、社交媒体）→ 自底向上。先抽出来，再用聚类和频次把高频模式沉淀成本体。
  • 大型工业图谱几乎都是混合：阿里新零售是“人、场、货”本体先定，再融合国内、海外、线下三大市场的多源异构数据，达到百亿级实体、千亿级关系边。

易错点：不要说“自顶向下就是人工、自底向上就是自动”。两者都可能用自动工具，区别在本体是先定还是后归纳。

§2 发展历程：分几个阶段

考点：五个阶段、每阶段的时间、标志性事件、解决了什么问题。按时间顺序答，标志性事件一个都不能漏。

答法一（一句话）

知识图谱的发展经历萌芽、工程化、形式化、互联网、知识图谱五个阶段，标志分别是从专家系统到知识工程、从本体到语义网、从语义网到 2012 年 Google 正式提出知识图谱。

答法二（标准版：五段各两句）

阶段 时间与标志 核心贡献 局限
① 萌芽 1965 年 Feigenbaum 提出专家系统（Expert System） 符号主义：人类认知是基于符号表示的运算，用逻辑表达模拟思维。基于领域知识库 + 推理机解决问题，是知识库的最早雏形 知识靠人工录入，规模小、领域窄、维护难
② 工程化 1977 年第五届国际人工智能会议，Feigenbaum 提出知识工程 把数据、信息、知识整合到结构化的图形化表示中，目标是构建丰富、连贯、可操作的知识体系，支撑搜索、推荐、问答 仍是手工为主，规模、来源、质量有限
③ 形式化 1991 年 Niches 提出知识本体概念，1993 年 Gruber 定义为“概念体系的明确规范” 把领域知识形式化，提供共享的语义框架；概念可被计算机处理、可群体共享，使知识图谱从理论研究走向大规模工程实践 本体构建成本高，缺乏统一标准
④ 互联网 1998 年 Tim Berners-Lee 提出语义网（Semantic Web） 用 RDF 在万维网上做知识表示与推理；出现大规模专家知识系统，第一代 DENDRAL 识别分子结构，第二代 MYCIN 做医疗诊断 网页标注率低，落地困难
⑤ 知识图谱 2012 年 Google 正式提出 Knowledge Graph（“Things, not Strings”） 与人工智能、大数据融合，构建走向半自动化、自动化；最大不同是出现跨域知识整合，开始整合同领域图谱，实现跨领域应用与共享 质量评估、时效性、隐私仍是问题

答法三（展开：一句话记住演进逻辑）

五个阶段其实在回答同一个问题的不同侧面：知识怎么表示（符号 → 规则 → 本体 → RDF/OWL）、知识从哪来（人工录入 → 半自动抽取 → 自动抽取）、知识用来干什么（诊断一个病人 → 服务全网搜索）。

所以演进的主线可以概括成：规模从小到大，来源从人工到自动，应用从单领域到跨领域。

记忆锚：1965 专家系统 → 1977 知识工程 → 1991/1993 本体 → 1998 语义网 → 2012 知识图谱。年份只记 1965、1977、1998、2012 四个，本体那两年记成“九十年代初”即可。

§3 知识图谱的分类

考点：四种分类方式，每种的类别名称。这里容易漏，因为四种方式混在一起。

答法一（一句话）

知识图谱可按知识模态、领域开放性、构建方法、元数据实现方式四个角度分类；此外还有时间、空间、多模态三类新兴类别。

答法二（标准版：四种方式逐条列）

（1）按知识模态

  • 结构化：以明确定义的数据结构表示，常存于数据库，含事实和关系，可用 SQL 等标准查询语言检索和操作。例：企业 ERP 表、关系库里的业务数据。
  • 半结构化：有部分结构形式但不具备严格数据模式。例：XML、JSON、HTML 标记、网页表格与 Infobox。
  • 非结构化：以自然语言形式存在，缺乏明确结构和格式。例：纯文本、图像、音视频。

（2）按领域开放性

  • 通用知识图谱：涵盖广泛的主题和领域，旨在覆盖人类知识的各个方面。例：Wikidata、DBpedia、YAGO。
  • 跨领域知识图谱：整合多个领域的知识，跨越不同领域之间的边界，提供更全面、更多样化的知识。
  • 垂直领域知识图谱：专注特定领域或行业（如医学），包含该领域专有的术语、概念和关系，满足特定领域需求。例：中医药语义网络、金融知识图谱。
  • 企业内部知识图谱：构建于特定组织或企业内部，用于管理和组织内部知识资产，可涵盖产品信息、客户关系等。

（3）按构建方法：自顶向下、自底向上、混合（详见 §1）。

（4）按元数据实现方式

  • 基于模式（Schema）：预先定义模式来构建和管理数据，适合数据结构固定、规则明确、需要高效查询与推理的场景。
  • 基于本体（Ontology）：以本体定义概念、关系和属性，不仅描述结构，还包含关系的语义和逻辑，能解释关联与层次结构。
  • 基于标签（Tags）：用标签描述和组织实体与关系，不依赖严格结构和预定义本体，加标签即可灵活描述特征，适合快速演化的场景。

（5）新兴类别

  • 时间知识图谱：$\varepsilon$（实体集）、$R$（关系集）、$\Gamma$（时间戳集），每个事实用四元组表示，是 $g\in\varepsilon\times R\times\Gamma$ 的集合。
  • 空间知识图谱：在实体中加入时空属性，能查询某时刻或时间段内的实体关系，并可在一定程度上计算空间距离。
  • 多模态知识图谱：模态指某种类型的信息或其存储表示形式，如人的触觉、听觉、视觉、味觉、嗅觉；把图像、视频等非文本模态挂到图谱上。

答法三（展开：为什么会分出这么多类）

分类维度不同，回答的其实是不同的问题：

  • 按模态 → 回答数据从哪来、怎么抽。结构化走 D2R 映射，半结构化走 Web Table 抽取，非结构化走信息抽取。
  • 按开放性 → 回答知识覆盖多大范围。这一维直接决定本体怎么设计、质量怎么控。
  • 按构建方法 → 回答本体先定还是后归纳。
  • 按元数据实现 → 回答schema 用什么技术承载（关系表 / 本体语言 / 标签系统）。

易错点：把“通用/垂直”和“自顶向下/自底向上”混为一谈。前者是覆盖范围，后者是构建顺序，两个维度正交，垂直领域图谱也可以用自底向上做。

§4 知识图谱的技术内涵、构建流程、各环节解决什么问题

考点：这是全课程的总纲题，答案要能把六章串起来。答好了能把六章串成一条线。

答法一（一句话）

知识图谱是用图结构组织知识的技术体系：节点代表实体、边代表关系、边上的标签表示关系类型，由此形成 <头实体, 关系, 尾实体> 三元组；技术上由表示、抽取、融合、存储、推理、应用六个环节构成，目标是让机器理解数据并用关联关系解释现象。

答法二（标准版：内涵 + 流程 + 环节职责）

（一）技术内涵

知识图谱来源于语义网络，规模远大于常用的语义网络。它把各类互相关联的实体及其属性合理组织在一起，统一组织结构化、半结构化、非结构化信息，让计算机理解自然语言。

  1. 结构单元是三元组：<实体, 属性/关系, 实体或值>。实体是现实世界中的事物或概念（人、地点、组织、产品），每个实体有唯一标识符和若干属性；属性是实体或关系的特性；关系是实体之间的联系；本体是对实体、属性和关系进行分类与定义的方法，通常含分类层次。
  2. 图的语义来自边上的标签：同一对节点用不同标签连，含义完全不同。“马云 —isa→ 快餐店”与“马云 —母公司的母公司→ 百胜餐饮”是两件事；自然语言句子只给了“肯德基”这个入口，是图谱提供了消歧所需的上下文。
  3. 要解决的是“机器可算”：符号化、结构化之后才能做查询、推理、统计。这也是它与文本库（Text as KB）、向量库（Embeddings as KB）并列的三种知识库形态之一：文本库靠 BERT/GPT 从语言里取知识，向量库把词、实体、对象都学成一个向量，知识图谱靠图结构显式建模关联。

（二）技术要素

表示（属性图 / RDF 图 / OWL 本体建模 / 规则表示）→ 存储（关系图存储 / 原生图存储 / 图查询语言）→ 抽取（概念抽取 / 实体识别 / 关系抽取 / 事件抽取）→ 融合（实体对齐 / 本体映射 / 概念匹配）→ 推理（符号推理 / 规则推理 / 图推理 / 神经网络推理）→ 问答（问句理解 / 语义解析 / 答案生成）→ 分析（图算法 / 图嵌入 / 图神经网络 / 图可视化）→ 其它（众包、Scene Graph、Semantic IoT）。

（三）构建流程与各环节解决的问题

环节 输入 输出 解决什么问题
知识表示 概念与关系 三元组、本体、向量 机器怎么算：把世界知识变成计算机能存、能算的形式
知识抽取 结构化/半结构化/非结构化数据 实体、关系、事件、规则 知识从哪来：把非结构化文本变成结构化三元组
知识融合 多来源三元组 一致、去冗余的图谱 多源怎么统一：消除同一实体的多种表述，消解冲突
知识存储 三元组集合 某种物理布局 + 查询能力 怎么查得快：让多跳查询不用层层 JOIN
知识推理 已有边 + 规则/模型 新边、隐含分类、置信度 缺的边怎么补：从已知推出未知
知识应用 图谱 搜索、问答、推荐、风控 用来干什么：把关联关系变成业务价值

答法三（展开：一条主线把六章串成一句话）

表示的粒度决定抽取的目标，抽取的质量决定融合的难度，融合的结果决定存储的形状，存储的形状决定推理的代价。

  • 表示选了向量，抽取就要输出能训练的（h, r, t）；表示选了 RDF，抽取就要对齐到本体里的类与属性。
  • 抽取出来的实体名有三种写法（万达集团 / 大连万达集团股份有限公司 / Wanda Group），融合就得做实体对齐。
  • 融合后仍有多值冲突（一个库记董事长、一个记创始人），合并就得做真值发现。
  • 存储选了关系库，三跳查询要 27 次自连接；选了原生图库，靠免索引邻接只访问局部子图。

第二部分 知识表示

§5 知识表示的内涵

考点：定义、五种角色、边界（不是什么）、在知识库形成中的位置。定义几乎必考。

答法一（一句话）

知识表示（KR）是用计算机模型和方法表示、处理知识，以支持推理、学习和决策等智能行为；一句话说，用易于计算机处理的方式描述人脑的知识。

答法二（标准版：定义 + 位置 + 五种角色）

（1）定义的两层含义

它不只是存储信息，还包括如何构造信息，使计算机能理解并利用这些信息模拟人的智能活动。所以“存下来”只是第一步，“构造得能让机器推理”才是关键。

（2）在知识库形成中的位置

知识库的形成分五个阶段：知识认知 → 知识收集 → 知识表示 → 知识库建立 → 知识库维护，彼此紧密相连、相互依赖。知识表示是中间环节，起关键作用。前面两步的成果要在这里变成机器能处理的形式，后面两步都建立在它的形式上。

（3）五种角色（Davis、Shrobe、Szolovits，1993）

角色 内涵
替代物 Surrogate 客观事物的机器标识（Entity ID），用符号代替真实对象参与运算
本体约定集合 一组本体约定和概念模型，规定世界里有哪些东西
智能推理理论 支持推理的表示基础，形式决定能推什么
高效计算媒介 用于高效计算的数据结构
人类表达媒介 人可理解的机器语言

五者彼此牵制：既要人可理解，又要易于计算，还要能承载推理，并有明确的概念模型与机器标识。任何一种表示方法都只能在这五个要求之间取平衡，不可能全占。

（4）边界：它不是什么

KR 不是数据格式，不等同于数据结构，也不是编程语言。对人工智能而言，数据与知识的区别在于 KR 支持推理：一张 Excel 表是数据，一套能推出“王思聪的爷爷是谁”的三元组加规则才是知识。

答法三（展开：用途与三句补充）

主要应用于专家系统、自然语言处理、机器学习、智能搜索引擎、机器人。作用是提高推理能力、增强解释能力、促进知识共享。

三句可以补进答案的话：

  • 表示形式决定了推理能力的上限。用一阶逻辑能表达量词，用属性图就表达不了全称约束；用向量能算相似度，但推不出严格结论。
  • 表示形式也决定了学习成本。符号表示要人写规则，向量表示要数据训练。
  • 知识图谱之所以要“图”，是因为它比表多了一样东西：路径。有了路径，“王思聪 → 父亲 → 王健林 → 任职于 → 万达集团”这条链才存在，才能回答“王思聪和万达集团什么关系”。

§6 两类知识表示：原理、优势、局限、适用场景

考点：符号表示与向量表示的对立。这是本章最容易出比较题的地方，按“标准—对比—结论”三段写。

答法一（一句话）

知识表示分两大类：符号表示（属性图、RDF、OWL 等）把知识写成显式的节点与边，可解释、可推理，但构建成本高、泛化差；向量表示（TransE、RotatE、SMN 等）把实体与关系学成低维稠密向量，可计算、可泛化，但不可解释、精度有损。

答法二（标准版：先原理，再四条标准对比）

（一）符号表示的原理

用节点和边显式描述实体及其关系，基本组成是节点、边、属性、三元组、类型。

  • 属性图：顶点、边、标签、关系类型、属性组成的有向图。节点与边都可带属性，属性以任意键值形式存在。例：Person(name='Tom Hanks', born=1956) -[ACTED_IN {roles:['Forrest']}]-> Movie(title='Forrest Gump', released=1994)。
  • RDF：三元组 (subject, predicate, object) 描述资源，主语通常是实体，谓词是关系或属性，宾语可以是值或另一实体。语法有 RDF/XML、Turtle、N-Triples、JSON-LD 四种。RDFS 提供 Class、subClassOf、type、Property、subPropertyOf、Domain、Range 这组词汇，可做简单推理。
  • OWL：完备的本体语言，提供等价类、传递性、互反、函数性、对称性、局部约束（全称限定 allValuesFrom、存在限定 someValuesFrom、基数限定 cardinality）等构件；三元组不够用时的终极手段。

（二）向量表示的原理

把离散符号变成稠密向量，起点是词向量：One-hot 与词袋维度等于词典大小 k，稀疏且不携带相似性；词向量把维度压到 d，且 d ≪ 词典大小。依据是分布式语义：“You shall know a word by the company it keeps”（Firth, 1957），词的语义由它被使用的上下文确定。

类别 代表 核心思想
基于向量空间距离 TransE、TransR 关系视为平移（或先投影到关系空间再平移），用 $\lVert h+r-t\rVert$ 度量三元组成立的程度
基于语义匹配 SMN、ESM 用神经网络把实体与关系编码，在表示空间里做匹配并打分
基于旋转与双曲几何 RotatE、RotH 关系即复数平面（或双曲空间）中的旋转，约束 $t=h\circ r$
面向动态图谱 TGAT、TTransE 引入时间切片、时间嵌入或时间向量 $t_{\text{time}}$，刻画知识随时间演化

（四）适用场景

  • 选符号：领域规范、要求结论可审计、需要严格推理。医疗诊断（一条结论要能追溯到指南）、金融合规（监管要求可解释）、企业主数据（结构稳定、schema 明确）。
  • 选向量：数据规模大、需要补全与推荐、允许概率性结论。链接预测、实体对齐、推荐系统、跨模态检索。
  • 现实做法是混用：用符号表示存骨干事实，用向量表示做候选生成与排序；符号保证准确，向量保证覆盖。第一章提到“Embeddings as Knowledge Base”与“KG as Knowledge Base”并列，说的就是这两条路线并存，而不是替代关系。

历史上符号表示走过五步：语义网络（Quillian, 1966）→ 产生式规则与专家系统（DENDRAL、MYCIN）→ 框架系统（Minsky）→ 描述逻辑与 DAML+OIL（Horrocks）→ 语义网 RDF 与 OWL（Berners-Lee）。四条早期路线各有明确的长短板：

§7 TransE：内涵、评分函数、计算

考点：这是全课程最可能出计算题的地方。公式、几何直觉、训练损失、算例，四件都要会。

答法一（一句话）

TransE 把三元组 (h, r, t) 中的实体与关系都映射到同一个 d 维实向量空间，把关系看作从头实体到尾实体的平移向量，于是 $h+r\approx t$；评分函数 $\mathrm{E}(h,t,r)=\lVert h+r-t\rVert$，值越接近 0 表示三元组越可能成立。

答法二（标准版：内涵 + 公式 + 训练）

（1）核心假设：关系是一次平移

如果“王健林 父亲 王有富”成立，那么向量上应该有 $\text{王健林}+\text{父亲}\approx\text{王有富}$。这个假设带来两个直接好处：一是参数少，每个实体一个向量、每种关系一个向量，没有额外的矩阵；二是能推，给定 h 和 r，落点附近最近的实体就是候选尾实体，链接预测因此变成最近邻搜索。

代价也很明确：一套实体空间要同时装下所有关系。一对多（一个父亲有多个孩子）、对称（朋友、配偶）、自反这几类关系在纯平移下必然失效，因为同一个 h 加同一个 r 只能落在一个点上，装不下多个 t。这是 TransR、RotatE 出现的直接原因。

（2）评分函数

$$ \mathrm{E}(h,t,r)=\lVert h+r-t\rVert\qquad (L_1\ \text{或}\ L_2\ \text{范数}) $$
  • 用 L1：各维差取绝对值再求和，鲁棒、好算。
  • 用 L2：各维差平方求和再开方，对大偏差更敏感。
  • 值越小越好，等于 0 表示完全吻合。

（3）训练：margin 排序损失

只让正样本距离小是不够的：所有向量都缩到 0，距离也会小。所以要成对比较：真三元组的距离要比假三元组小至少一个 margin $\gamma$，差得不够就罚。

$$ L=\sum_{(h,r,t)\in S}\ \sum_{(h',r,t')\in S'}\max\bigl(0,\ f_r(h,t)+\gamma-f_r(h',t')\bigr) $$
  • S 是真实三元组集合，S′ 是负样本集合，由随机替换头实体或尾实体构造。
  • $\gamma$ 是 margin，通常取 1。
  • 初始化：实体与关系按 $\mathrm{uniform}(-6/\sqrt{k},\ 6/\sqrt{k})$ 初始化并归一化；每轮取 batch $b$，对每个正例采样一个损坏三元组，按梯度更新。

（4）算法步骤

  1. 初始化所有实体向量与关系向量，并做单位化。
  2. 取一个 batch 的正样本。
  3. 对每个正样本，随机替换 h 或 t，构造一个负样本。
  4. 按 $L=\sum\bigl[\gamma+d(h+r,t)-d(h’+r,t’)\bigr]_{+}$ 计算损失，反向传播更新。
  5. 每轮结束重新归一化实体向量（防止靠缩短向量来降低距离）。

答法三（计算例题，务必会手算）

例题 1：给定向量，判断三元组真假并排序

设维度 $d=3$，已知：

$$ \begin{aligned} &\text{王思聪}=(1,2,0),\qquad \text{父亲}=(1,-1,1)\\ &\text{候选尾实体：}\ \text{王健林}=(2,1,1),\ \text{万达集团}=(0,0,1),\ \text{王有富}=(3,3,2) \end{aligned} $$

第一步，算平移落点：

$$ h+r=(1+1,\ 2-1,\ 0+1)=(2,1,1) $$

第二步，逐个算距离：

候选 t t 向量 差 (h+r−t) L1 距离 L2 距离
王健林 (2,1,1) (0,0,0) 0 0
万达集团 (0,0,1) (2,1,0) 3 $\sqrt{5}\approx2.24$
王有富 (3,3,2) (−1,−2,−1) 4 $\sqrt{6}\approx2.45$

第三步，写结论：王健林距离为 0，判为正确尾实体；三个候选的排序是 王健林 < 万达集团 < 王有富。

答题要写的话：L1 与 L2 给出的排序一致，本例中 L1 更好算。若题目只要求判断真假，答“距离为 0 的三元组成立，其余不成立”即可。

例题 2：算 margin 损失

已知正样本距离 $f_r(h,t)=0.5$，负样本距离 $f_r(h’,t’)=2$，$\gamma=1$。

$$ L=\max(0,\ 0.5+1-2)=\max(0,\ -0.5)=0 $$

不产生损失：正负样本差了 1.5，已经超过 margin 1，模型认为排序正确，不再罚。

若负样本距离只有 0.8：

$$ L=\max(0,\ 0.5+1-0.8)=0.7 $$

罚 0.7：虽然正样本比负样本好，但好得不够（只差 0.3，达不到 1），要推开。

这道小题背后是 TransE 训练的全部思想：把正负样本**拉开到至少 $\gamma$**。“差得不够就罚”这句话值得写出来。

例题 3：为什么必须重新归一化

假设不归一化，模型发现“把所有向量乘 0.1”能同时缩小正样本与负样本距离，于是正样本距离从 0.5 降到 0.05、负样本从 0.8 降到 0.08，差值从 0.3 缩到 0.03，反而更容易触发惩罚。但若整体缩放，损失不会真的下降，优化器会乱走。所以每轮把实体向量归一化到单位球面上，让模型只能通过改方向来降低距离。

TransE 与 TransR 的差别（常一起考）

TransE TransR
空间 实体与关系同一个 $d$ 维空间 实体空间 $\mathbb{R}^d$，关系空间 $\mathbb{R}^k$，且 $k\neq d$
关系处理 关系就是一个平移向量 $r$ 每个关系一个映射矩阵 $M_r$，先把实体投影到关系空间（$h_r=hM_r$，$t_r=tM_r$），再在关系空间内平移
参数量 少，$(\lvert E\rvert d+\lvert R\rvert d)$ 多，每个关系一个 $d\times k$ 矩阵
能力 简单关系好，一对多/对称失效 能处理实体在不同关系下语义不同的问题，但参数大、易过拟合

§8 Skip-gram 核心思想

考点：这是 DeepWalk 的前置，两章都用到。核心是“用中心词预测上下文”。

答法一（一句话）

Skip-gram 用中心词预测它周围的上下文词：把中心词编码成向量，经隐层映射后预测窗口内每个位置该出现什么词，训练完成后隐层权重就是词向量。

答法二（标准版：机制 + 与 CBOW 的对照）

（1）机制（六步）

  1. 中心词取 one-hot 向量，长度为词典大小 $V$。
  2. 乘中心词矩阵（$V\times n$），得到 $n$ 维隐层表示（$n$ 是可调的特征维数，远小于 $V$）。
  3. 乘上下文矩阵（$V\times n$），得到 $V$ 维得分向量。
  4. softmax 归一化，得到词典中每个词作为上下文的概率。
  5. 概率最大的词即预测词。
  6. 预测与真实上下文不符时，用反向传播修正两个权重矩阵 W 与 W′。

第 4 步的概率写成式子，$w_I$ 是中心词，$w_O$ 是窗口里的某个上下文词，$v$ 与 $v’$ 分别是中心词矩阵和上下文矩阵里对应的行向量。

$$ p(w_O\mid w_I)=\frac{\exp\bigl(v'^{\top}_{w_O}v_{w_I}\bigr)}{\sum_{w=1}^{V}\exp\bigl(v'^{\top}_{w}v_{w_I}\bigr)} $$

（2）训练样本怎么来

句子 “I always go to work by bus”，对 work 取窗口 2，上下文是 go、to、by、bus，于是得到四个训练样本：{x=work, y=go}、{work, to}、{work, by}、{work, bus}。词典 10000 词时，每个词编码为 10000 维 one-hot（对应位置为 1、其余为 0）；隐层行数 10000、列数为特征数。

（3）与 CBOW 的差别

CBOW Skip-gram
预测方向 用上下文预测目标词 用目标词预测上下文，逐个考虑周围每个词
结构 上下文向量求平均后预测，结构简单、训练快、能处理大规模语料 逐词预测，表达更细粒度
效果 高频词表现好 通常更好，低频词也更准

两者共享同一套词向量参数，只是训练信号不同。

答法三（展开：为什么这个思想能用到图上）

Skip-gram 把“词义”变成了共现统计的副产物：经常出现在相似上下文里的词，学到的向量自然相近。“苹果”孤立出现时分不清是水果还是手机品牌，放进句子才明确。

这个机制可以搬到图上，因为图和句子有严格的结构对应：

句子 图
单词 节点
句子序列 随机游走生成的节点序列
上下文（窗口内的词） 邻域结构（游走窗口内的邻居）

于是在图上随机游走生成节点序列，把序列当句子喂给 Skip-gram，就能得到节点向量，这就是 DeepWalk 的全部思路。目的是得到合理的向量，预测任务只是手段，这句话要写。

代价：Skip-gram 的 softmax 分母要对整个词典求和，$V=10000$ 时计算量很大，所以实践中用负采样（只从噪声分布抽几个负例）或层次 softmax 近似。LINE、Node2Vec 都用了负采样。

第三部分 知识抽取

§9 知识抽取与命名实体识别的内涵

考点：两个定义 + 三个基础任务 + 五个阶段。这是本章开篇题。

答法一（一句话）

知识抽取是自动化地从文本中发现并抽取相关信息，把多个文本碎片中的信息合并，将非结构化数据转换为结构化数据；命名实体识别是其中最基础的一步：检测实体的边界并判别它的类型。

答法二（标准版：概念 + 三个基础任务 + 五个阶段）

（1）知识抽取的概念

最早在 20 世纪 70 年代后期出现于自然语言处理领域，21 世纪初期随知识图谱兴起，2010 年代中期后迅速发展（Google 2012 年推出 Knowledge Graph 是标志）。工程视角看，知识图谱就是从不同来源、不同结构的数据中提取知识，形成知识存入图谱。

数据分三类，对应四条落地路径：

数据类型 例子 落地路径
结构化 链接数据、数据库 图谱融合、D2R 转换语义集成
半结构化 表格、列表、Infobox Web Table 抽取
纯文本 新闻、报告 Information Extraction

抽取出的知识沉淀为概念、实体、关系、事实、事件、规则，由此形成五类抽取技术：概念（术语）抽取、实体抽取、关系抽取、事件抽取、规则抽取。

（2）从文本获取知识的三个基础任务

  • 术语抽取（概念抽取）：从语料中发现由多个单词组成的相关术语。
  • 命名实体识别：检测实体边界并分类。例：“库克非常兴奋”中库克是实体、类型为人物。
  • 关系抽取：例：“王思聪是万达集团董事长王健林的独子”抽出 [王健林] <父子关系> [王思聪]。

（3）五个阶段

  1. 数据预处理：数据收集（确定范围与来源、选择收集策略、保证质量）、数据清洗（去重、去噪、纠错）、数据标注（为实体与关系加标签，需遵循标注规范以保证准确一致）。
  2. 实体抽取：命名实体识别（人名、地名、机构名等特定类型）+ 实体扩展（在已识别实体基础上用规则与算法抽取相关或相似实体）。
  3. 关系抽取：关系模式发现（分析潜在关系）+ 特征提取（句法路径、词向量、上下文）+ 关系分类（分为购买、亲属、雇佣等类型）。
  4. 事件抽取：事件触发词识别（触发词可为动词、名词或形容词）+ 事件论元抽取（参与者、时间、地点）。
  5. 后处理与评估：结果校验（人工或自动审核、与已有知识库比对、专家反馈）+ 效果评估（准确率、召回率、F1）。

注意：这些阶段并不完全独立，彼此存在交叉和重叠。这句话别漏。

答法三（命名实体识别的内涵，单独展开）

命名实体识别（NER）又称实体识别，是知识图谱构建的基础性工作，也是关系抽取、事件抽取等更复杂结构抽取的前提。

任务目标：从文本中识别代表实体的边界并判别其类型。既包括命名实体（人名、地名、组织机构名），也包括领域特定实体（日期、时间、货币）。

基本原理：对文本做语法和语义分析后识别并提取其中的特定实体。

本质是序列标注（这是最容易漏的一句）：

  • 分类任务：输入 X₁…Xₙ 与输出 Y₁…Yₘ 相互独立。
  • 序列标注：输入是特征序列、输出是类别序列，标签之间存在依赖。

正因为有依赖，才需要 CRF 这类能建模标签转移的模型：B 后面不该接 O（一个实体的首字后面必须跟内部字或结束字），这个约束普通分类器学不到。

难点：标签分布不平衡、实体嵌套；中文特有的困难在缺乏自然分词、词汇变化多样、简化表达这三处。英文 NER 已因 RNN、LSTM、Transformer、BERT 取得显著进展，中文 NER 在新实体涌现方面仍待提升。

例子：「北京时间 10 月 25 日，骑士后来居上，在主场以 119-112 击退公牛。」要标出地点、时间、组织三类实体。

§10 HMM 的 A、B、π 分别代表什么

考点：三要素是必考填空，还要能说出对应的三个基本问题。给个算例更稳。

答法一（一句话）

HMM 的三要素 $\lambda=(A,B,\pi)$。**$A$ 是状态转移概率矩阵，$A_{ij}$ 表示从状态 $i$ 转移到状态 $j$ 的概率；$B$ 是发射（观测）概率矩阵，$B_j$ 表示在状态 $j$ 下生成某个观测的概率；$\pi$ 是初始状态概率分布**，表示序列开头处于各个状态的概率。

答法二（标准版：三要素 + NER 里的对应关系）

（1）HMM 是什么

描述时间序列的统计模型，用于刻画含隐含未知参数的马尔可夫过程。在 NER 中，把每个词的标注视为隐藏状态、词本身为观测序列，训练学到词与标注之间的概率分布，再在给定观测序列时预测最可能的标注序列。

（2）三要素逐个说清

符号 名称 维度 含义 在 NER 里管什么
$\pi$ 初始状态概率向量 $1\times N$ 序列第一个位置处于各状态的概率，$\sum_i\pi_i=1$ 管开头：句子第一个字是 B 还是 O 的先验
$A$ 状态转移概率矩阵 $N\times N$ $A_{ij}=P(\text{状态 }j\mid\text{状态 }i)$，从 $i$ 转到 $j$ 的概率 管相邻标签的搭配：B 后面接 I 的概率高、接 O 的概率低
$B$ 发射概率矩阵 $N\times M$ $B_j(k)=P(\text{观测 }k\mid\text{状态 }j)$，状态 $j$ 生成观测 $k$ 的概率 管字与标签的对应：“王”这个字在 B-PER 状态下出现的概率

（3）三个基本问题（三要素各管一个）

基本问题 已知 求 算法
① 概率计算（评估） $\lambda$ 与观测序列 $O$ $P(O\mid\lambda)$ 前向算法 / 后向算法
② 学习（参数估计） 观测序列 $O$ 使 $P(O\mid\lambda)$ 最大的 $\lambda$ Baum-Welch（EM 的一种）
③ 解码（预测） $\lambda$ 与观测序列 $O$ 最可能的状态序列 $I$ Viterbi 算法

$\pi$ 管开头、$A$ 管转移、$B$ 管发射。

答法三（计算例题，会算一条路径的概率）

题目：给定 HMM，参数如下。

$$ \begin{aligned} \pi&=(\pi_B,\ \pi_I,\ \pi_O)=(0.6,\ 0.1,\ 0.3)\\ A_{B\to I}&=0.8,\qquad A_{I\to I}=0.7,\qquad A_{I\to O}=0.2\\ B_B(\text{王})&=0.5,\qquad B_I(\text{健})=0.6,\qquad B_I(\text{林})=0.5,\qquad B_O(\text{林})=0.1 \end{aligned} $$

求观测序列“王 健 林”在两条候选路径下的概率，并选出最优路径：

  • 路径甲：(B-PER, I-PER, I-PER)，即“王健林”是一个完整人名
  • 路径乙：(B-PER, I-PER, O)，即“王健”是人名，“林”不是

算路径甲：

$$ \begin{aligned} P(\text{甲})&=\pi(B)\cdot B(B,\text{王})\cdot A(B\to I)\cdot B(I,\text{健})\cdot A(I\to I)\cdot B(I,\text{林})\\ &=0.6\times0.5\times0.8\times0.6\times0.7\times0.5\\ &=0.3\times0.8\times0.6\times0.7\times0.5\\ &=0.0504 \end{aligned} $$

算路径乙：

$$ \begin{aligned} P(\text{乙})&=\pi(B)\cdot B(B,\text{王})\cdot A(B\to I)\cdot B(I,\text{健})\cdot A(I\to O)\cdot B(O,\text{林})\\ &=0.6\times0.5\times0.8\times0.6\times0.2\times0.1\\ &=0.3\times0.8\times0.6\times0.2\times0.1\\ &=0.00288 \end{aligned} $$

结论：0.0504 > 0.00288，取路径甲，“王健林”整体标为 PER。

答题格式：先写 $P(\text{路径})=\pi(\text{首状态}),B(\text{首状态},\text{首观测})\prod A(\text{转移}),B(\text{发射})$，再代数，最后写 argmax。这条公式是拿分点。

顺带一个判据（可能出选择题）：路径甲比乙大 17 倍多，主要差在 $A_{I\to O}=0.2$ 与 $B_O(\text{林})=0.1$ 这两项上。HMM 会偏好“标签连贯”的解释，这也是它的局限：局部概率高不等于全局最优，所以做 NER 时常常在 HMM 之上换成 CRF 做全局归一化。

HMM 的局限（常连着问）

HMM 成立需要两个假设：齐次性（状态转移只依赖前一个状态）与观测独立性（当前观测只依赖当前状态）。后者在 NER 里问题很大。“王”这个字在“王健林”和“王府井”里都出现，但如果看上下文（前面的“住在”还是“拜访”），判断会完全不同，HMM 用不了这些上下文特征。CRF 就是为解这个来的：它对所有特征全局归一化，可求全局最优，输出时依赖整个输入序列。

§11 “bot 模型”的内涵

说明：「bot 模型」不是标准术语，题目里出现的可能是下面三者之一。按可能性排序，先答 BERT，再补另两个。

可能一：BERT（最可能）

答法一（一句话）：BERT 是双向编码器表示（Bidirectional Encoder Representations from Transformers），基于 Transformer 架构的预训练语言模型，用大规模无标注文本预训练、再用少量标注数据微调，输出每个词的上下文相关向量。

答法二（标准版）：

  1. 架构：多层 Transformer 编码器。Transformer 由 2017 年《Attention Is All You Need》提出，开启大模型时代。
  2. 预训练两个任务：掩码语言模型（MLM）随机遮住部分词让模型猜，损失 $L_{\mathrm{MLM}}=-\frac{1}{N}\sum_i\log p(\hat{w}_i\mid\text{上下文})$，$N$ 为词总数；下一句预测（NSP）判断两个句子是否相邻，损失 $L_{\mathrm{NSP}}=-\frac{1}{M}\sum\bigl[\mathrm{IsNext}\cdot\log p+(1-\mathrm{IsNext})\cdot\log(1-p)\bigr]$，$M$ 为样本数。
  3. 微调：在特定任务（文本分类、命名实体识别）上加任务输出层，用少量标注数据调参。
  4. 对 NER 的意义：直接以字的向量为输入，端到端，不再依赖人工定义特征；不同神经网络结构充当编码器，最后经 CRF 输出每个词的标注结果。
  5. 对实体链接的意义：让“一词多义”的判别从特征工程变成表示学习：同一个词在不同句子里向量不同，上下文自动进入表示。

答法三（展开）：相比词袋与 Word2Vec，BERT 的三个不同：① 双向，同时利用指称左右两侧的上下文；② 动态，表示随语境变化（Word2Vec 一个词一个固定向量）；③ 预训练 + 微调，任务只需少量标注。

可能二：BoW / 词袋模型

一句话：词袋模型（Bag-of-Words）把文本看成词的集合，忽略词序，用词典大小 k 维的计数向量表示文本；One-hot 是它的极端形式（每个词一个 k 维向量，只有一位为 1）。

要点：维度等于词典大小 k，稀疏且不携带相似性：“苹果”与“华为”的 one-hot 向量内积为 0，模型看不出它们都是公司。词向量把维度压到 d 且 d ≪ k，才携带相似性。这个对比是第二章讲词向量的起点。

可能三：BiLSTM-CRF（“B” 系列的模型）

一句话：BiLSTM-CRF 用前向、后向两个 LSTM 分别编码句子再拼接，得到每个位置的双向上下文表示，末端接 CRF 层建模标签之间的转移关系并做全局最优解码。

数据流：one-hot 向量经 look-up 层得字向量 $x_i\in\mathbb{R}^d$ → 前向/后向 LSTM 的两个隐状态拼接成 $h_t\in\mathbb{R}^m$ → 线性变换得打分矩阵 $P\in\mathbb{R}^{n\times k}$（$p_{ij}$ 为字 $x_i$ 归入第 j 个标签的分数）→ CRF 层按 $\mathrm{score}(X,y)=\sum(\text{标签得分}+\text{转移得分})$ 找最高分路径，训练用对数似然损失。

LSTM 的三门（常一起问）：遗忘门 $f_t=\sigma(W_f[h_{t-1},x_t]+b_f)$，决定丢弃哪些旧信息（新主语到来时忘掉旧主语的性别）；记忆门把新信息写入细胞状态；输出门决定输出哪部分状态。细胞状态按 $C_t=f_t\odot C_{t-1}+i_t\odot\tilde{C}_t$ 更新，$h_t=o_t\odot\tanh(C_t)$。

为什么加 CRF：LSTM 输出的每个标签是独立打分，可能出现 B-PER 后面接 O 这种非法序列。CRF 层引入转移得分，让“非法转移”得分极低，保证输出标签序列全局最优。这也呼应了 §12 的标签体系：有了 BIO 的约束，CRF 才有意义。

§12 不同标签标注体系分别表示什么

考点：IO / BIO / BIOES 三段含义 + 对比。给例子更稳。

答法一（一句话）

标签体系决定怎么表示实体的边界：IO 只分实体内部与外部；BIO 用 B 标首字、I 标内部、O 标外部；BIOES 再加 E（实体结束）与 S（单字实体），边界信息最全。

答法二（标准版：三种体系 + 逐字示例）

例：“习大大将于周日返京”

Token IO BIO BIOES
习 I-PER B-PER B-PER
大 I-PER I-PER I-PER
大 I-PER I-PER E-PER
将 O O O
于 O O O
周 I-DATE B-DATE B-DATE
日 I-DATE I-DATE E-DATE
返 O O O
京 I-LOC B-LOC S-LOC
。 O O O

（1）IO

只区分实体内（I）与实体外（O）。“习大大”三个字都是 I-PER，“周日”两个字都是 I-DATE。

问题：相邻的两个同类实体无法区分。若文本是“张三李四都来了”，七个字（三、李是边界）都会标 I-PER，解码时分不清是一个四字人名还是两个人名。

（2）BIO（也称 BIO1）

  • B（Begin）：实体的第一个字
  • I（Inside）：实体的内部字（非首字）
  • O（Outside）：非实体

“习大大”是 B-PER、I-PER、I-PER。B 标出了起点，解决了 IO 的边界歧义。

（3）BIOES（也称 BILOU、BIO2 的一种）

  • B（Begin）：实体首字
  • I（Inside）：实体内部
  • E（End）：实体末字
  • S（Single）：单字构成的实体

“京”是一个单字地名，标 S-LOC；“大”是“习大大”的末字，标 E-PER。

好处：B 与 E 同时给出两端，S 单独处理单字实体。边界完全确定，解码不用猜。

（4）其他常见体系（知道名字即可）

  • BMEO / BMES：B、M（Middle）、E、O，与 BIOES 的差别是不单独设 S，单字实体用 B-E 或 E 表示。
  • BIO2 / BIO1 区分：BIO1 不区分实体类型边界，BIO2 的 B、I 后都带类型后缀（B-PER、I-PER），能直接看出类型切换。

答法三（展开：为什么越复杂越准，以及怎么选）

准确度：大部分情况下标签体系越复杂准确度越高，但训练时间也相应增加，需按实际情况选择。

原因：标签越多，类别数 k 越大，模型要学的转移约束越多。BIOES 的 E 与 S 让“实体必须闭合”这个约束可以被模型直接学到；IO 则把这个信息完全丢掉，只能靠后处理规则切分。

怎么选：

  • 实体多、边界重要（人名、机构名多字为主）→ BIOES。
  • 训练资源紧、实体短→ BIO 也够用。
  • IO 只适合“不关心边界、只关心是否实体”的粗粒度任务，如实体提及检测。

一个必须知道的联动：标签体系决定 CRF 转移矩阵的形状与合法转移集合。用 BIO 时，B 后面允许 I 或 O，不允许直接 B（两个实体相连时中间必须插 O 或用 BIOES）；用 BIOES 时，B 后面允许 I 或 E，S 后面不能再接 I。这套约束就是 CRF 里“非法路径要拦住”的具体内容。

§13 实体抽取：基于规则 vs 基于机器学习

考点：两条路线的做法、优缺点、适用场景。按比较题模板答。

答法一（一句话）

规则法靠人工编写的正则、词典与模板去匹配文本，准确率高但构建费时、可移植性差；机器学习法把抽取转化为分类或序列标注问题，靠标注数据自动学特征，泛化好但依赖标注质量。

答法二（标准版：两条路线各自的做法 + 对照表）

（1）规则式抽取

原理：通过预先定义的规则来匹配、提取实体，规则可基于正则表达式、词典、语法模式。四个环节：

  1. 规则制定：依据领域语法语义规则编写抽取规则。
  2. 文本解析：解析待抽取文本，识别词性、句法结构。
  3. 规则匹配：把规则应用于解析后的文本，匹配成功的片段标注为特定类型实体并记录位置与属性。
  4. 实体输出：对规则冲突用优先级或上下文分析策略消解，输出 JSON 或 XML 等结构化信息。

典型做法：把文本与“*说”“*老师”“*大学”“*医院”这类模板匹配。

（2）基于机器学习的抽取

原理：把实体（关系）抽取问题转化为二分类或多分类问题，用机器学习算法对大量样本做特征编码、建模与训练，形成能预测未知文本关系模式的模型。最重要的思想是获取实体的特征信息。

序列标注流程：确定标签体系 → 选择模型 → 定义特征 → 模型训练。

特征类别 内容 例子
词本身的特征 边界词概率、词性、依存关系 “先生”暗示前面是人名
前后缀特征 姓氏、地名后缀 姓氏“李XX”“王X”，地名“XX省”“XX市”
字本身的特征 是否是数字、是否是字符 “1984”可能是年份

常用模型：HMM（三要素 $A$、$B$、$\pi$）、CRF（全局归一化）、SVM（最大间隔 + 核函数）。

（3）对照表（答案主体）

标准 基于规则 基于机器学习
知识来源 语言学专家手工编写 标注数据中自动学习

（4）实际做法

工业系统普遍用“规则打底 + 模型补充”：规则保证高精度与可解释（如身份证号、时间、金额这类强模式），模型保证召回（如人名、机构名这类弱模式）。这也符合 §9 讲的“实体扩展”环节：先识别核心实体，再用规则与相似度扩展到边界情况。

答法三（展开：两句话点出各自的根本局限）

规则法的根本局限是“人写的规则永远写不全”。中文尤其难：同一个人名可以写成“王健林”“王董”“老王”“万达的王董事长”，规则要枚举到哪一层？每加一条规则，冲突的可能性就多一分。

机器学习法的根本局限是“学到的规律来自标注数据”。如果训练集里没有“万达集团”这种四字机构名，模型就可能认不出。所以标注规范的一致性比标注数量更重要：两个人标同一句话标出两套标签，模型学到的就是噪声。

近年趋势：深度学习消除人工特征（端到端），BERT 让表示随语境动态变化，但标注数据依然是瓶颈，所以远程监督、Bootstrapping、少样本学习这些“少标注”路线一直在发展。

第四部分 知识存储

§14 知识存储的作用

考点：定义 + 三个关键词 + 四个价值 + 与“数据堆砌”的区别。这题不要答得太薄。

答法一（一句话）

知识存储是知识管理的核心组成部分，通过结构化、组织化、联结化把知识组织起来，让知识更易访问、更有用、可被利用，从而支撑快速检索、复杂查询与推理。

答法二（标准版：定义 + 三个关键词 + 四个价值）

（1）三个关键词

关键词 含义
结构化 按统一模型组织知识（三元组、属性图、RDF）
组织化 建立分类与层次关系（本体、类型层次）
联结化 用关系把知识连成网络（边、指针、邻接）

目标是从数据走向可用的知识。

（2）知识存储 ≠ 数据堆砌

数据堆砌只做收集与保存、不做组织：信息散落各处、缺乏统一模型、查询靠人工翻找、无法支撑自动化分析与推理。知识存储在此基础上增加结构化、组织化、联结化与可访问（支持快速检索与更新）。维基百科正是通过分类与链接组织知识，让用户顺着条目获取全面信息。

（3）四个核心价值

  1. 检索效率：结构化组织快速定位知识，减少信息过载。
  2. 决策质量：及时获取准确完整的信息，支撑科学高效的决策。
  3. 创新能力：整合分析发现新的连接，跨领域融合激发新创意。
  4. 可持续性：知识资源系统化沉淀，实时更新以适应环境变化。

（4）存储对象

实体（图谱中独立的节点，如李华、李想）、关系（连接两实体的有向边，如朋友、任职、出生于）、属性（描述实体特征的值，如姓名、年龄、城市）。三者构成三元组 $(\text{头实体},\ \text{关系},\ \text{尾实体})$，这是知识图谱的基本构成单元。

答法三（展开：为什么“存储决定查询”）

这句话是全章的题眼，答论述题时值得单独说。

同一个问题“王健林的朋友的朋友是谁”，在不同存储上的代价完全不同：

  • 关系库三元组表：一跳要一次自连接，两跳要临时表加两次自连接，三跳四次……SQL 长度随跳数指数增长，可读性极差。
  • 二元表：每次跳要 join 一张新表，表数量随谓词数增长。
  • 原生图库：节点直接持有邻居指针，遍历只访问局部子图，查询时间与图的整体规模无关，只与搜索的局部大小成正比。

所以存储不只是“存在哪”，它决定了什么问题能问、什么问题的代价可接受。这也是为什么第 5 章开头用电商推荐举例：存储做不好，多层关系查询需要大量 JOIN，数据量增长后查询越来越慢，个性化推荐难以实时响应。

存储的价值在于让关联查询变得便宜。

§15 两类知识图谱存储的比较

考点：关系库（四种子方案）vs 原生图库。这是比较题 + 可能出选择/填空。

先分清是哪两种「两类」。 「两类」通常指两种结构化存储形式：基于关系型数据库与基于原生图数据库，所以标准答案是关系库 vs 图库。如果老师问的是 RDF 存储 vs 属性图存储，那是另一个维度（数据模型层的三分：RDF 三元组库、属性图库、关系表），区别在于 RDF 以三元组为唯一结构、便于标准交换与推理，属性图把属性挂在节点和边上、便于工程建模但推理能力弱。答之前看清题目问的是“存储实现”还是“数据模型”。

答法一（一句话）

知识图谱有两条存储路线：关系数据库把三元组拆成行与列、靠 SQL 与索引查询，成熟通用但多跳查询要层层 JOIN；原生图数据库以节点为实体、边为关系、靠免索引邻接遍历，多跳快但生态较新。

答法二（标准版：关系库四种子方案 + 图库原理 + 总对照表）

（一）关系数据库的四种子方案

（1）三元组直接存储

每个三元组映射为一行，表含 Subject / Predicate / Object 三列。

Subject Predicate Object
李华 朋友 李想
李华 朋友 王平
李想 朋友 田英
李华 父亲 李尚

优点：无需额外建模设计、表结构一目了然、复用成熟关系库能力，适合快速原型与教学。
索引优化：在 Subject、Predicate 建索引，避免全表扫描；可用组合索引覆盖常用查询。
三个局限：① 表结构固定，难以表达复杂关系与多值属性；② 图谱一扩展就要加列或加表，变更伴随数据迁移与停机；③ 多跳查询要层层 JOIN：查“李华的朋友的朋友”就要建临时表加自连接，三跳四跳时 SQL 急剧膨胀。

（2）属性表

每个实体存为一行，每个属性存为一列。人物表含 ID / Name / Age / Gender / Location。

优点：属性读写快，支持筛选、排序、聚合。
两个局限：① 表数量爆炸，真实图谱实体类别可达数千种，每类一张表，往往超出数据库上限；② 空值问题，同类实体属性差异大，必须预留大量列位，未使用字段置空，浪费空间又拖慢查询。属性表擅长“同类同构”的实体。

（3）二元表

每张表只表达一种关系，通常只含头实体、尾实体两列，列中存实体唯一标识（ID）。

HeadID TailID
1 2
1 4
4 6

优点：把“关系”变成一等公民，无空值、每谓词独立可扩展，可加列记录方向或权重。
局限：查询要 join 多张表，表数量爆炸（谓词有多少，表就有多少）；语义靠列名与约定承载，图结构是隐式表达的。

协同使用：属性表存实体属性，二元表存实体关系，通过唯一标识相互关联，一次查询可跨表取到完整信息。

（4）索引表

用额外的表存指向主表的索引，至少两列：一列存索引键（如人物姓名），一列存主表记录引用（如 ID）。三步：确定索引键 → 构建索引表 → 维护索引（随主表更新同步）。
优势：显著减少查询时间，可定制专用索引；代价：额外存储空间，高写入负载下维护开销大。设计者要在“查询性能”与“存储及维护成本”之间找平衡点。

（二）原生图数据库

核心原理：免索引邻接（index-free adjacency）。访问邻接关系无需额外索引，每个节点维护邻居的引用，引用如同一个个“微索引”。因为节点直接指向邻居，查询时间与图整体规模无关，仅与搜索的局部大小成正比。查一个朋友的成本是 $O(1)$，再深一跳也只与局部邻接数量有关。

对比关系库：每一跳都要查一次索引，查询次数随深度增长，大规模下性能明显衰减。

存储块三部分：节点存储（含节点属性与关系信息）、关系存储（每条关系一个结构体，含起止节点标识符）、属性存储（分内联与动态两种）。

内联存储 Inline 动态存储 Dynamic
做法 属性直接嵌入节点存储结构，与标识信息放在一起 属性存于单独存储区域，节点与引用关联
优点 省去指针开销，属性与标识物理连续，可按位置寻址，访问快 结构灵活，可动态增删属性，无需重新分配节点空间
适用 属性小且查询频繁 属性大或不常查询

选择依据是“属性数据的大小 × 访问频率”，工程中常常并存。

（三）总对照表（答案主体）

维度 关系数据库 原生图数据库
数据模型 行与列组成的表，三元组映射为记录 节点与边组成的网络，与图谱结构同构
查询语言 SQL Cypher、Gremlin
索引机制 用索引指针连接相关数据，每跳查一次索引 免索引邻接，节点直接持有邻居引用
多跳查询 需层层 JOIN，深度越大 SQL 越长、性能衰减越快 遍历只访问局部子图，与全图规模无关
模型灵活性 数据结构相对固定，修改需迁移与重构 结构灵活，分布式架构易扩展修改
事务与一致性 强，完整支持 ACID（原子性、一致性、隔离性、持久性） 支持 ACID（Neo4j），但分布式下通常牺牲强一致
可视化 通常不提供内置可视化，需额外工具 内置可视化，直观理解关系
关系表达 通过外键隐式表示实体间关系 显式存储，关系是可直接查询的数据实体
生态成熟度 高，技术成熟、SQL 生态完善、运维经验多 相对较新，运维经验积累较少
适用场景 结构化业务数据、强一致性事务、简单过滤与聚合统计 社交网络、风控图谱、知识图谱等复杂关联与深链分析

（四）图库的四大优势

① 免表连接遍历；② 查询性能优越（复杂路径与关联高效处理）；③ 图特性直算（节点的度、路径长度直接算）；④ 结构灵活直观。

（五）选型四维度

规模 Scale（单机还是分布式）、复杂度 Complexity（是否多跳遍历、属性是否多值）、查询需求 Query（简单过滤还是深度遍历、是否需内置图算法）、成本 Cost（存储与维护开销、团队技术栈成熟度）。

答法三（展开：三代演进 + 一句结论）

图数据库自身也在演进：

代 时间 代表 特点 局限
第一代 单机原生 2002—2010 Neo4j 小规模原生图存储，无需索引即可遍历，极大减少系统开销 扩展性差，受单机性能上限约束，不支持分布式
第二代 分布式非原生 2010—2016 JanusGraph 扩展性显著提升，应对大数据时代数据量激增 查询性能比第一代低，难支持多跳深链查询，非原生带来额外开销
第三代 原生分布式 2017 至今 — 兼得原生遍历与分布式规模，实时图分析，与 AI 平台融合 运维复杂度高

演进逻辑：先解决“存”，再解决“扩”，最后解决“算得快”。第一代用原生存储换查询效率、牺牲扩展性；第二代用查询性能换扩展性，多跳成为新短板；第三代要两样都要。

关系库胜在成熟通用，图库胜在关系遍历。两者可以并用，大量系统是关系库存业务主数据、图库存关联分析，用 ID 打通。所以选型看的是查询长什么样。

第五部分 知识融合

§16 知识融合的流程

考点：五步流程 + 三类任务 + 两个层面 + 分块的必要性 + 相似度计算。这是本章最可能出大题的地方。

答法一（一句话）

知识融合分五步：数据预处理、数据分块、记录链接、负载均衡、结果评估；核心是三类任务（实体链接、知识对齐、知识合并）与两个层面（数据层、概念层）。

答法二（标准版：为什么融合 + 五步 + 两个层面）

（1）为什么要融合

四个常见场景导致不融合的代价：查一个人要在多个网站反复检索；同一实体在不同库中名称不同；A 库有的关系 B 库完全没有；两个库对同一属性给出不同取值。后果是知识覆盖率低、问题答不全，推理结果可能自相矛盾，冗余存储推高维护成本，错误知识被不断放大传播。

核心问题是如何让来自不同来源的知识，看起来像来自同一个大脑。

（2）异构从哪来（两个层面各四种）

语言层异构（决定“怎么表达”） 模型层异构（决定“怎么理解”）
语法异构：格式与语法不同 概念化异构：建模方式不同
逻辑异构：推理规则不同 解释异构：含义理解不同
表达异构：描述粒度不同 粒度异构：抽象层次不一
原语异构：建模原语不同 元模型异构：模式语言不同

（3）三类核心任务与两个层面

层面 对象 核心工作 输出
数据层融合 实体与属性值 实体对齐与匹配，判断不同库的实体是否同指 等价实例对应关系
概念层融合 概念、类与关系 本体对齐与映射，统一概念的语义解释 等价概念对应关系

三类任务：实体链接（把文本指称映射到知识库实体，解决多词一义与一词多义）、知识对齐（建立图谱元素之间的对应，含本体对齐、实体对齐、属性对齐）、知识合并（把已对齐的知识写入同一图谱，并检测与消解冲突）。

数据层解决“是不是同一个东西”，概念层解决“是不是同一个意思”。

（4）五步流程（重点）

第一步：数据预处理

  • 语法正规化：同一条信息有多种写法，如电话 010-6278 与 0106278、地址全称与简称并存，不统一将直接导致匹配失败。两种手段：语法匹配（统一书写格式）、综合属性（多字段拼接比较）。原则是不改变语义的前提下，把同一事实写成同一种形式。
  • 数据正规化四类操作：移除特殊符号与多余空格、拼写纠错与大小写统一、标准化命名与单位换算、日期与数值类型转换。典型：2024/1/5 → 2024-01-05，1.5km → 1500m，北科大 → 北京科技大学，全角符号统一为半角。

第二步：数据分块（Blocking）

  • 为什么必须分块：两两比较的复杂度是 $O(n^2)$，百万级数据无法穷举。分块把比较限制在块内，在效率与覆盖率之间折中。
  • 本质：用“便宜的规则”先筛掉绝大多数不可能匹配的记录对。
  • 两个关键：分块键决定哪些记录同块；块大小过大仍慢、过小漏配。目标是缩小候选对规模，同时保持召回率不下降。
  • 常用方法：
    • Hash 分块：简单分块用单一键做哈希（按邮编、按出生年份）；多重分块用多个键分别建块再取并集以提升召回率。
    • Canopy 聚类：先用粗粒度距离划 Canopy，$T_1$ 宽决定块的最大范围，$T_2$ 窄决定是否同块，适合高维大规模场景。
  • 共同原则：宁可在块内多比一些，也不要在块外漏掉真正的配对。

第三步：记录链接

两步走：先判断属性像不像，再判断实体是不是同一个。

  • 属性相似度三条路线：编辑距离（面向字符串）、集合相似度（Dice、Jaccard）、向量相似度（TF-IDF）。按属性类型选择度量。
  • 实体相似度两条路线：聚合（加权平均、规则判定、分类器 SVM/决策树）与聚类（SL 单链接取簇间最大相似度、CL 全链接取最小、AL 平均链接取平均）。此外还有表示学习（知识嵌入匹配）。
  • 多属性投票能抵消单一属性带来的噪声。

第四步：负载均衡

分块后各块大小不均匀，个别超大块会拖慢整体，需要把计算均匀分布到节点，通常靠多次 Map-Reduce 完成：Map 按块键分发记录，Reduce 做块内两两比较，多轮迭代避免数据倾斜。算法再好，块倾斜也会让集群空转。

第五步：结果评估

用混淆矩阵算准确率、精确率、召回率、F1（详见 §18）。若漏掉真实匹配的代价很高，应优先优化召回率 R：FN 的代价决定了这个优先级。

答法三（展开：两个必考的子问题）

子问题一：为什么分块不会降低召回率？

严格说分块可能降低召回：如果真匹配的两条记录在任何一把键上都不相同，它们就永远进不了同一个块。所以分块的设计目标是“用多把键互相兜底”：

例：A 表是 CRM 客户主数据（A1 王小明 / A2 李静 / A3 张伟），B 表是订单系统用户（B1–B4，其中 B2 是李静但出生年录错成 1992，B4 是另一个同名李静）。用出生年份、手机后 4 位、邮编三把键分别建块后取并集，得候选对 4 个 (A1,B1)(A2,B2)(A2,B4)(A3,B3)。真匹配召回 3/3 = 100%，代价是 1 个假阳性；比较次数从 12 降到 4。

B2 的出生年错了，靠年份键匹配不上，但手机后 4 位能匹配，这就是“多把键兜底”。

子问题二：编辑距离怎么算？

编辑距离（Levenshtein）是两个字符串的最少编辑次数，操作为插入、删除、替换，距离越小越相似，归一化用 $1-d/\max(\lvert s_1\rvert,\lvert s_2\rvert)$。

递推公式

$$ D(i,j)=\min\bigl\{D(i-1,j)+1,\ D(i,j-1)+1,\ D(i-1,j-1)+\mathrm{cost}\bigr\} $$

其中 $\mathrm{cost}$ 在 $s_1[i]=s_2[j]$ 时为 0、否则为 1。

算例：$s_1$ 取 “Lvensshtain”、$s_2$ 取 “Levenshtein”，需要 1 次删除加 2 次替换，编辑距离为 3。

另外两个度量也要会算：

  • Dice 为 $\mathrm{Dice}=\frac{2\lvert A\cap B\rvert}{\lvert A\rvert+\lvert B\rvert}$，Jaccard 为 $\mathrm{Jaccard}=\frac{\lvert A\cap B\rvert}{\lvert A\cup B\rvert}$，先把字符串切成 n-gram 集合再求交并。同一对字符串切成 2-gram 后 $\mathrm{Dice}\approx0.82$。集合相似度对词序颠倒与局部差异更鲁棒，适合姓名与短文本。
  • TF-IDF：TF 是词项在文档中的频次，$\mathrm{IDF}=\log\bigl(N/\text{含该词文档数}\bigr)$，权重为 $\mathrm{TF}\times\mathrm{IDF}$。语料 $N=50000$、某词出现在 100 篇，$\mathrm{IDF}=\log(500)\approx6.2$，结合 TF 得权重约 0.012。价值在于常见词权重低、区分性强的词权重高。

子问题三：Canopy 的 $T_1$、$T_2$ 怎么用？

$T_1$ 是宽阈值（如 0.30），$T_2$ 是窄阈值（如 0.70）。

  • 相似度 $>T_2$：强匹配，进同一块，且从候选集中移除（不再作为新的 Canopy 中心）。
  • $T_1<$ 相似度 $<T_2$：够粗糙，允许进同一块，但保留在候选集里，还可以当中心。
  • 相似度 $<T_1$：不同块。

关键性质是 Canopy 允许重叠：一个点可以同时落在多个块里。企业名消歧的例子中，3 个 Canopy、块内候选对 7 个（全量两两为 15），压缩约一半；c6 同时落在两个块里，说明它“还没被强匹配吃掉”。

§17 知识合并

考点：定义 + 前提 + 两层合并 + 三类来源的方法 + 八个步骤 + 冲突检测与消解。这题最容易答成“合并就是把两个图拼起来”，那就错了。

答法一（一句话）

知识合并是在实体对齐已完成、等价关系已知的前提下，把已对齐的知识写入同一图谱，并在合并过程中检测与消解知识冲突，产出规模更大、覆盖更全的新图谱。

答法二（标准版：前提 + 两层 + 三类来源 + 八步 + 冲突处理）

（1）前提与两层

前提是实体对齐已完成。合并分两层：模式层合并整合类、属性、关系；数据层合并整合实体、属性值。

对齐解决“是不是同一个”，合并解决“合起来之后以谁为准”。

（2）知识冲突

指不同来源对同一事实描述不一致，例：两个库中“生日”属性值相差一天。类型有属性值冲突、关系冲突、结构冲突。

（3）三类数据来源的合并方法

来源 方法 要点
外部知识库 LDIF（Linked Data Integration Framework） 面向 Web 规模的链接数据集成，声明式配置、流程可复现。四步：知识获取（抓取导入）→ 概念匹配（对齐本体中的类与属性）→ 实体匹配（对齐并合并等价实体）→ 知识评估（检查质量、输出结果）。概念匹配先于实体匹配，逐层推进
关系数据库 RDB2RDF Direct Mapping 直接映射：表→类、主键→实体 URI、列→属性、外键→关系，全自动无需写规则，缺点是生成名称可读性差。R2RML 自定义映射：声明式定义映射规则，可定制类名、属性名与目标词表，语义清晰可维护，缺点是规则编写量大
半结构化数据 XSPARQL、Datalift 来源为 XML、CSV、JSON，统一转 RDF 三元组。要点：先解析结构抽实体与属性，把字段语义对齐到目标本体，与已有图谱做实体对齐后合并，注意日期、编码、嵌套等格式差异

共同第一步：无论结构化还是半结构化，合并的第一步都是“统一到 RDF 数据模型”。结构化数据是知识图谱最重要的来源，RDB2RDF 是打通两者的标准通道。

③ 属性对齐 统一属性语义 ⑦ 冲突检测消解 以可信值为准
④ 关系对齐 统一关系语义 ⑧ 质量评估 抽检与指标验证

冲突检测与消解是合并区别于简单拼接的分水岭，也是本流程的关键环节。

（5）冲突的检测与消解（重点）

检测：扫描同一实体的同名属性取值集合，值不一致即标记为潜在冲突；区分真冲突与格式/单位差异（1.5km 与 1500m 属于没正规化，不算冲突）；冲突日志留存，供人工核查回溯。

消解要给同一实体的冲突值定一个结论，常用的做法有四条。

  1. 真值发现：从多源值中估计真实值（多数来源一致的那个更可能是真的）。
  2. 可信度赋值：按数据源质量加权（官方库权重高于众包库）。
  3. 投票 / 多数原则：少数服从多数。
  4. 无法判定时保留多值并标注来源：宁可留两条带出处的值，也不要随机挑一个。

目标：在自动化的同时保留证据链，让每一个取值都可追溯。

答法三（展开：一个具体例子走完全流程）

假设两个库要合并“王健林”：

  • A 库（企业工商注册）：王健林，职务=董事长，生日=1954-10-24，来源可信度高。
  • B 库（财经媒体）：王健林，职务=创始人，生日=1954-10-24，来源可信度中。
  1. 预处理：都不需要（格式已统一，若要合并 B 库的“大连万达集团股份有限公司”才需要正规化成“万达集团”）。
  2. 实体对齐：靠姓名 + 生日 + 关联企业判定 A 库的王健林与 B 库的王健林是同一个人，概率 0.98 > 阈值 0.95，判等价。
  3. 属性对齐：“职务”与“职位”是同义属性，“生日”与“出生日期”是同义属性。
  4. 关系对齐：“任职于”与“就职于”是同义关系。
  5. 模式层合并：把两库的“人物”类、“企业”类合并，属性表取并集。
  6. 数据层合并：王健林一个节点，属性取并集。
  7. 冲突检测消解：生日两边一致（1954-10-24），无冲突；职务一边“董事长”一边“创始人”，是真冲突 → 用可信度赋值，取 A 库的“董事长”，同时保留“创始人”作为历史职务并标注来源 B 库。
  8. 质量评估：抽检 100 个合并后的实体，核对属性冲突是否都被标记。

拼图是 1+1=2，合并是 1+1=1.2（去重、消解、补全），多出来的 0.2 是冲突处理与证据链。

§18 混淆矩阵的计算

考点：TP/FP/FN/TN 四个量 + 四个指标公式 + 会算。给两道例题。

答法一（一句话）

混淆矩阵把预测结果与实际结果交叉成四格：TP（预测匹配且实际匹配）、FP（预测匹配但实际不匹配）、FN（预测不匹配但实际匹配）、TN（预测不匹配且实际不匹配）；由此算出准确率、精确率、召回率与 F1。

答法二（标准版：四格 + 四公式 + 一个完整算例）

（1）四格的含义

预测匹配 预测不匹配
实际匹配 TP（真正例） FN（假负例，漏报）
实际不匹配 FP（假正例，误报） TN（真负例）

（2）四个指标

指标 公式 含义
准确率 ACC (TP + TN) / 总数 整体判对的比例
精确率 $P$ $\frac{TP}{TP+FP}$ 预测为匹配的里面有多少真的对
召回率 $R$ $\frac{TP}{TP+FN}$ 真实匹配被找出了多少
F1 值 $F_1=\frac{2PR}{P+R}$ 兼顾精确率与召回率的调和平均

（3）算例一

预测匹配 预测不匹配 行合计
实际匹配 TP = 40 FN = 10 50
实际不匹配 FP = 5 TN = 45 50
列合计 45 55 100
$$ \begin{aligned} \mathrm{ACC}&=\frac{40+45}{100}=0.850\\ P&=\frac{40}{40+5}=0.889\\ R&=\frac{40}{40+10}=0.800\\ F_1&=\frac{2\times0.889\times0.800}{0.889+0.800}=0.842 \end{aligned} $$

（4）算例二（换成融合任务的场景，练手）

两个图谱做实体对齐，共 200 个候选实体对，其中真实匹配 60 对。系统判为匹配 70 对，其中 50 对是对的。

$$ \begin{aligned} \mathrm{TP}&=50\\ \mathrm{FP}&=70-50=20\\ \mathrm{FN}&=60-50=10\\ \mathrm{TN}&=200-50-20-10=120 \end{aligned} $$
$$ \begin{aligned} \mathrm{ACC}&=\frac{50+120}{200}=0.850\\ P&=\frac{50}{70}=0.714\\ R&=\frac{50}{60}=0.833\\ F_1&=\frac{2\times0.714\times0.833}{0.714+0.833}=0.769 \end{aligned} $$

答题格式：先把四格算出来，再代公式，每步写清分子分母。F1 一定要写 $F_1=2PR/(P+R)$，不要写 $(P+R)/2$。后者是算术平均，是常见扣分点。

答法三（展开：三个可能被追问的点）

追问一：为什么 F1 用调和平均而不是算术平均？

精确率与召回率通常此消彼长：把阈值调低，召回上去但误报多、精确率下来；调高则相反。算术平均会让“一个极高、一个极低”的组合拿到中等分，掩盖短板。调和平均对小的那个更敏感：$P=1.0$、$R=0.1$ 时算术平均 0.55，调和平均只有 0.18。所以 F1 逼你两头都要顾。

追问二：ACC 为什么可能骗人？

类别不平衡时 ACC 会失真。假设 1000 个候选对里只有 10 对真匹配，一个把所有对都判为“不匹配”的懒惰系统：

$$ \begin{aligned} \mathrm{TP}&=0,\ \mathrm{FP}=0,\ \mathrm{FN}=10,\ \mathrm{TN}=990\\ \mathrm{ACC}&=990/1000=0.99\quad\text{（看起来很好）}\\ R&=0/(0+10)=0\quad\text{（实际什么都没找到）}\\ F_1&=0 \end{aligned} $$

所以融合任务必须同时报 P、R、F1，不能只报 ACC。漏掉真实匹配的代价高时，应优先优化召回率 R。

追问三：什么时候优先精确率、什么时候优先召回率？

看 FN 与 FP 哪个代价大：

  • FN 更贵 → 优先召回。例：风控名单匹配、司法案例检索，漏掉一个真风险比多查几个假警报更糟。
  • FP 更贵 → 优先精确。例：自动合并客户主数据，错合并会把两家公司的订单混在一起，修复成本极高。
  • 一般做法：先用高阈值保精确，再人工复核 FP；或用低阈值保召回，再用更强的模型二次排序。

§19 DeepWalk

考点：思想、类比、四步流程、与 Node2Vec 的差别。

答法一（一句话）

DeepWalk 把随机游走生成的节点序列当句子，用 Skip-gram 学节点向量；它是第一个把 NLP 思想用到图嵌入的模型（Perozzi 等，KDD 2014）。

答法二（标准版：动机 + 类比 + 四步 + 优劣）

（1）动机：图数据难以直接计算

规模庞大、结构复杂，节点与边没有固定顺序，邻接矩阵高维稀疏，缺少统一的特征表示，CNN 与 RNN 都难以套用。图表示学习（图嵌入）就是把图结构数据转换为低维向量：节点和边被映射到低维空间，结构信息被压缩并保留，向量可直接计算、分类、聚类。目标是原始图中相似的节点在低维空间中也彼此接近。

（2）类比关系（这是 DeepWalk 的核心洞见）

句子 图
单词 节点
句子序列 随机游走生成的节点序列
上下文（窗口内的词） 邻域结构

句子对应游走序列，单词对应节点，上下文对应邻域结构。随机游走生成的节点序列就相当于一个句子，节点相当于句子中的单词。

（3）随机游走的定义

一种可重复访问已访问节点的遍历算法：从图中任意节点开始，按邻接表或转移概率矩阵随机选择一个邻接节点移动，重复下去得到一条游走路径；每条路径都相当于一个句子。

（4）四步流程

  1. 图输入：节点索引、边索引、邻接矩阵。
  2. 随机游走：对每个节点执行多次随机游走，生成大量节点序列。
  3. 训练 Skip-gram：把序列当作句子输入，用中心节点预测上下文节点。
  4. 更新参数：反向传播更新，得到节点的低维向量表示。

（5）优势与局限

优势：简单有效、易于实现，无需人工设计节点特征，社交网络分析与推荐系统中表现良好。
局限：游走策略单一（均匀随机、无偏），倾向捕捉局部结构、可能忽略全局结构特征；游走长度与游走路径数量都会影响嵌入质量。

这一局限正是 Node2Vec 的改进出发点。

答法三（展开：参数与代价）

关键参数：

参数 含义 取值
num_walks 每个节点游走次数 10
walk_length 每次游走长度 20
embed_size 向量维度 50
window Skip-gram 窗口 5
sg 1 表示用 Skip-gram，0 表示 CBOW 1

代价分析：游走本身很便宜（每步 $O(\text{walk_length})$），但序列总量是 $N\times\text{num_walks}\times\text{walk_length}$，Skip-gram 训练是主要开销；且 softmax 分母要对全部节点求和，实际用负采样近似。

根本局限是“查表”：DeepWalk 学到的是每个节点一个固定向量，本质是一张 $N\times d$ 的查找表。新节点加入时表里没有位置，只能重新训练，这叫直推式（transductive）。这个局限直接催生了 GraphSAGE。

Node2Vec 怎么改：把均匀随机换成二阶有偏游走，用 p、q 两个参数控制：

  • p 控制是否回游（退回上一个节点）。p 小 → 更容易回退，游走偏 BFS 式，停留在局部。
  • q 控制向内或向外探索。q 小 → 更愿意往外走，游走偏 DFS 式。

两种游走捕捉两种性质。DFS 捕捉同构性（结构等价），距离很远的节点可能有相似的结构角色（航空网络的枢纽机场、公司的中层管理者）；BFS 捕捉同质性（相似相连），直接相连或共享邻居的节点应彼此接近（社交好友圈、科研团队）。

§20 GCN

考点：为什么需要、传播公式、自连接与归一化的作用、局限。

答法一（一句话）

GCN 把卷积从欧几里得空间推广到图结构，用对称归一化的邻接矩阵聚合邻居特征，逐层堆叠；核心公式是 $H^{(l+1)}=\sigma\bigl(\tilde{D}^{-1/2}\tilde{A}\tilde{D}^{-1/2}H^{(l)}W^{(l)}\bigr)$。

答法二（标准版：动机 + 公式 + 两个设计 + 优劣）

（1）动机：规则数据与图数据的差别

图像、文本等欧几里得结构排列整齐、邻居数量固定，平移不变性与局部性原则成立，卷积核可以直接在网格上滑动。图数据（社交网络、分子结构）的节点连接模式不规则，每个节点可能有不同的邻居数量和连接类型，不遵循欧几里得空间中的距离或维度概念。局部性原则不再适用，CNN 依赖规则局部窗口、RNN 依赖序列先后顺序，都难以直接处理图。

卷积的图推广：把卷积理解为“滤波器在局部邻域内加权求和、窗口大小固定、参数在整张图上共享”，在图上就换成“节点与其邻居节点之间传递信息”，邻居数量可变，但聚合方式统一。

（2）传播公式

$$ H^{(l+1)}=\sigma\Bigl(\tilde{D}^{-1/2}\ \tilde{A}\ \tilde{D}^{-1/2}\ H^{(l)}\ W^{(l)}\Bigr) $$
  • $H^{(l)}$、$H^{(l+1)}$：第 $l$ 层与下一层的节点特征矩阵（$N\times d$）
  • $\tilde{A}=A+I$：添加自连接后的邻接矩阵
  • $\tilde{D}$：$\tilde{A}$ 的度矩阵（对角阵，对角元素是节点度数）
  • $W^{(l)}$：该层可学习的权重矩阵
  • $\sigma$：非线性激活函数（如 ReLU）

（3）两个关键设计（必须解释清楚的两点）

**① 自连接 $\tilde{A}=A+I$**：让节点在聚合时保留自身的特征信息。不加 $I$ 的话，节点更新后自己的信息就丢了，只看邻居。等价的说法是“把自环当成一种特殊的关系”。

**② 对称归一化 $\tilde{D}^{-1/2}\tilde{A}\tilde{D}^{-1/2}$**：使特征聚合中每个节点的贡献与其度数成反比，避免度数高的节点对结果过度影响；归一化后不同节点的聚合结果尺度一致，训练更稳定。这是 GCN 能稳定训练的关键设计之一。

直观理解：如果只做求和（$\tilde{A}H$），度数 100 的节点聚合结果的数值量级会是度数 2 的节点的 50 倍，逐层堆叠后数值爆炸；除以度数后，每个节点的聚合结果都变成“邻居的加权平均”，量级一致。

（4）优点与局限

优点：把卷积从欧几里得空间推广到图结构，通过对称归一化邻接矩阵聚合邻居信息，训练流程简单清晰，理解 GCN 对理解后续模型意义重大。

局限有三条。

  • 需要整张图参与训练（全图训练），内存开销受限。
  • 层数加深容易过平滑，节点表示趋于相似。原因是每层都在做平均，几层之后所有节点都变成全图均值附近，区分度消失。
  • 属于直推式，新节点加入要重训。

答法三（计算例题 + 复杂度）

例题：手算一层聚合

设三个节点 A、B、C，A 连 B 和 C。特征向量（2 维）：

$$ h_A=[2,0],\qquad h_B=[0,2],\qquad h_C=[2,2] $$

不加自连接（只用邻居平均）：

$$ h'_A=\frac{h_B+h_C}{2}=\frac{[0,2]+[2,2]}{2}=[1,2] $$

加自连接（$\tilde{A}=A+I$，邻居集合变成 ${A,B,C}$）：

$$ h'_A=\frac{h_A+h_B+h_C}{3}=\frac{[2,0]+[0,2]+[2,2]}{3}=\left[\tfrac{4}{3},\tfrac{4}{3}\right]\approx[1.33,1.33] $$

结论：加自连接后，A 的表示里保留了自己的 [2,0]，第一维从 1 升到 1.33；不加的话第一维只剩 1，自身特征被稀释。

说明：上例用简单平均代替对称归一化，是为好算。真实 GCN 的权重是 $1/\sqrt{d_i d_j}$，当 B 的度数为 5、C 的度数为 10 时，C 的贡献会被压得更低。答题时可以补一句“真实实现用对称归一化，本例用平均以简化计算”。

复杂度：$O(\lvert E\rvert F)$，$F$ 是特征维数。因为邻接矩阵是稀疏的，聚合一次只需遍历所有边。

§21 GraphSAGE

考点：解决什么问题、三步流程、三种聚合器、与 GCN 的三个差别。

答法一（一句话）

GraphSAGE 用“邻居采样 + 可学习聚合器”替代全图卷积，学到的是聚合规则而不是节点查表，因此是归纳式（inductive）的，可以为训练时未见过的节点生成嵌入。

答法二（标准版：动机 + 三步 + 三聚合器 + 三差别）

（1）动机：直推式的两个硬伤

GraphSAGE 由斯坦福与 Google 的研究者 2017 年提出，用于生成高质量节点嵌入，解决大规模图上的归纳表示学习问题。传统图嵌入大多是传导式的，只能在训练时见过的节点上预测，新节点加入往往需要重新训练。

学习范式 直推式 transductive 归纳式 inductive
能力 只能在训练时见过的节点上预测，无法泛化到未见过节点 学到聚合规则而非节点查表，可为新节点生成嵌入
代表 GCN、DeepWalk；新节点需重训 GraphSAGE；适合大规模、动态变化的图

（2）三步流程

  1. 邻居采样：对每个节点的邻居做随机采样，可采用固定大小采样，也可按度数自适应，保证采样到足够丰富的局部结构信息。
  2. 聚合：把采样到的邻居特征聚合起来，形成该节点的新特征表示。
  3. 逐层重复：在每个搜索深度 k 重复，随迭代逐渐获得来自更远部分的信息。

采样保证计算量可控，聚合决定表达方式。

（3）三种聚合器

聚合器 做法 特点
均值聚合 Mean 计算邻居特征向量的逐元素平均值 最简单，与 GCN 的传播规则非常相似，可看作局部谱卷积的线性近似
LSTM 聚合 用 LSTM 对邻居序列编码 表达能力强，但 LSTM 本身不对称、按顺序处理输入，需通过随机排列邻居来适应无序集合
池化聚合 Pool 每个邻居向量先经全连接网络变换，再逐元素最大池化 既对称又可训练，理论上任何对称向量函数都可替代 max

均值聚合公式：$h_v^{k}\leftarrow\sigma\bigl(\tilde{D}\cdot\mathrm{MEAN}({h_v^{(k-1)}}\cup{h_u^{(k-1)},\ \forall u\in N(v)})\bigr)$。注意里面有 $h_v$ 自身，即带自连接。

池化聚合公式：$\mathrm{AGGREGATE}_{\mathrm{pool}}=\max\bigl({\sigma(W_{\mathrm{pool}}h_u^{k}+b),\ \forall u\in N(v)}\bigr)$。

（4）与 GCN 的三大区别

差别 GCN GraphSAGE
训练方式 需要整张图参与训练（全图批训练） 小批量采样训练，适合大规模图
未见节点 直推式，新节点要重训 归纳式，可为新节点生成嵌入
邻居聚合 对全部邻居加权求和，权重由度数固定 先采样固定数量的邻居，聚合函数可学习、可替换

答法三（展开：为什么“采样”能保证不丢信息）

这个问题常被追问。

采样的目的是让计算量可控且可分批。 一个节点的邻居可能有 5000 个，全聚合既慢又没必要，邻居里大量是噪声。固定采样 $k$ 个（如 $k=25$），两层就是 $25^{2}=625$ 个邻居节点参与计算，与图的规模无关。

代价是方差：每次采样不同，同一个节点的嵌入会略有波动。工程上的对策是训练时采样、推理时用全邻居或多次采样取平均。

复杂度：$O(\Pi^{K}N^{K}F)$，$K$ 是层数。看起来比 GCN 的 $O(\lvert E\rvert F)$ 大，但因为采样把 fanout 固定住了，实际训练开销与图规模解耦，这正是它能上十亿级图的原因。

一个记忆点：GCN 是“把邻居全部平均”，GraphSAGE 是“抽几个邻居学怎么平均”。前者参数少、依赖固定图结构；后者参数多、能迁移到新图。

§22 GAT

考点：注意力机制、公式、多头、与 GCN 的差别。

答法一（一句话）

GAT 用注意力机制为不同邻居分配不同权重：不再像 GCN 那样按度数固定加权，而是学出每对邻居的重要性系数 $\alpha_{ij}$，再用多头并行增强表达。

答法二（标准版：动机 + 注意力直觉 + 公式 + 多头）

（1）动机

GCN 依赖固定的邻接矩阵、对邻居统一赋权。邻居的重要性其实不同：判断“王思聪的投资风格”，王健林的影响远大于一个普通朋友。GAT 在聚合邻居特征时给每个邻居不同的注意力权重，自适应地学习节点的重要性而不依赖固定邻接矩阵，在复杂结构与动态变化的图上表现出色。

（2）注意力的直觉

模仿人类视觉注意力：第一次看一幅画时往往最先注意到画面中最突出的元素，听一段话时先抓住关键词，这是大脑快速筛选信息的方式。核心是通过学习输入数据的权重分布，识别对当前任务最关键的信息，而不是同等对待所有输入。

QKV 三元组：Query（查询）代表当前任务的需求；Key（键）与输入数据的特征相关联；Value（值）是输入数据的实际内容。计算 Query 与 Key 的相似度决定每个 Value 的权重，相似度加权求和就是注意力的本质。

（3）两个公式

注意力权重：

$$ \begin{aligned} \alpha_{ij}&=\frac{\exp(e_{ij})}{\sum_{k\in N(i)}\exp(e_{ik})}\\ e_{ij}&=\mathrm{LeakyReLU}\bigl(a^{\top}[Wh_i\,\Vert\,Wh_j]\bigr) \end{aligned} $$

节点特征更新（多头）：

$$ h'_i=\sigma\Bigl(\frac{1}{K}\sum_{k=1}^{K}\sum_{j\in N(i)}\alpha_{ij}^{(k)}W^{(k)}h_j\Bigr) $$

符号：$e_{ij}$ 是节点 $i$ 与 $j$ 的注意力分数；$a$ 是可学习的注意力向量；$\Vert$ 表示向量拼接；$\alpha_{ij}$ 经 softmax 归一化，权重越大邻居 $j$ 对 $i$ 的影响越大；$K$ 是头数。

（4）多头机制

K 个头并行计算各自的注意力分数，输出合并（拼接或平均），获得更丰富的节点表示。意义：不同头可以关注不同的邻居子集或不同的语义侧面，类似 CNN 的多个卷积核。

（5）实现细节（可能出填空）

前向顺序：线性投影 $h=XW$（$N\times D\to N\times F$）→ 拼接 $Wh_i$ 与 $Wh_j$ → LeakyReLU 得 $e_{ij}$ → 用邻接矩阵做掩码（非邻居位置置 −9e15）→ softmax 归一化 → 加权聚合 → ELU 输出。

掩码这一步很关键：softmax 是全局归一化，如果不把非邻居位置的分数压到极小，节点就会“注意到”本来不相连的节点。置 −9e15 而不是 −∞，是为了避免数值溢出。

答法三（展开：一个不用死算的判据）

例题（不做完整计算，只判断）

设节点 A 的三个邻居 B、C、D，注意力分数 $e_{AB}=0$、$e_{AC}=1$、$e_{AD}=2$。

问：三个权重谁最大？大概多少？权重之和是多少？

答：AD 最大，且 $e$ 分数每差 1，权重比约差 $e\approx2.7$ 倍。所以权重比约为 $1:2.7:7.4$，归一化后约为 **$0.09:0.24:0.67$**，三者之和必为 1。

一般不必真算 $e$ 的指数，但要会看“分数差 1 → 权重差 2.7 倍”这个关系，以及“softmax 后权重和为 1”这个性质。

与 GCN 的核心差异（常连着问）：

  • GCN 的权重由度数决定（$1/\sqrt{d_i d_j}$），是固定的、结构性的。
  • GAT 的权重由特征学出来（$a^{\top}[Wh_i,\Vert,Wh_j]$），是可学习的、内容驱动的。
  • 所以 GAT 能处理“邻居多但不重要”的情况，对噪声邻居更鲁棒；代价是多了一组参数 $a$ 与拼接投影，计算量约 $O(\lvert E\rvert FH)$。

§23 GCN、GraphSAGE、GAT 三个模型的比较

考点：这是本章的综合比较题，按先同、再异、后选型三层答。

答法一（一句话）

三者都用拓扑结构学节点表示，同属同构图神经网络；区别在邻居怎么选（全部 / 采样 / 加权）与参数怎么学（固定归一化 / 可学习聚合器 / 注意力）。

答法二（标准版：先同后异再选型）

（一）相同点（三条）

  1. 目标相同：都是用图的拓扑结构学习节点表示，让每个节点的表示既含自身特征、也含邻居信息。
  2. 范式相同：都遵循消息传递（message passing）范式，对节点 $v$，先由邻居 $u$ 生成消息 $m_{vu}=M(h_v,h_u,e_{vu})$，再聚合 $m_v=\mathrm{AGG}({m_{vu},u\in N(v)})$，最后更新 $h’_v=U(h_v,m_v)$。每层聚合一次，层数越深感受野越大。
  3. 定位相同：都面向同构图（节点与边只有一种类型），是入门后续异构模型（RGCN、RGAT、HAN、HGT）的基石。

（二）不同点（逐条比）

标准 GCN GraphSAGE GAT
邻居怎么选 全部邻居（权重由度数定） 随机采样固定数量 全部邻居，但权重可学
权重来源 固定为 $1/\sqrt{d_i d_j}$，结构性 可学习聚合器（mean/LSTM/pool） 注意力系数 $\alpha_{ij}$，内容驱动
参数 只有 $W^{(l)}$ $W$ 加聚合器参数 $W$、$a$、多头各自的投影
学习范式 直推式 transductive 归纳式 inductive 归纳式
训练方式 全图批训练 小批量采样 全图或小批量均可
新节点 需重训 可直接推理 可直接推理
时间复杂度 $O(\lvert E\rvert F)$ $O(\Pi^{K}N^{K}F)$ $O(\lvert E\rvert FH)$
主要问题 过平滑（层数多了表示趋同）、显存受限 采样带来方差、聚合器设计需权衡 参数量与计算量最大、注意力可能过拟合小图
适用 中小规模静态图，结构固定 大规模动态图，节点会新增 邻居重要性差异大，需要可解释权重

（三）递进关系（一句话串起来）

GCN 回答“怎么把邻居平均过来”，GraphSAGE 回答“邻居太多怎么抽、新节点怎么办”，GAT 回答“邻居不是一样重要”。三个问题依次是效率问题 → 泛化问题 → 权重问题。

答法三（展开：选型决策 + 一个统一视角）

选型决策（按条件写）

  • 只有结构、没有节点特征的大规模图 → DeepWalk 或 Node2Vec 做无监督基线（不用 GNN）。
  • 要显式兼顾直连与共同邻居 → LINE（一阶 + 二阶相似度）。
  • 节点边多类型、又不想引入 GNN → 元路径加 Metapath2vec。
  • 有节点特征、图规模不大且结构固定 → GCN。
  • 图很大或节点会新增 → GraphSAGE（采样 + 归纳）。
  • 邻居重要性差异大、要可解释的权重 → GAT（多头注意力）。

统一视角（答论述题时用）

把三种模型的聚合公式摆在一起看，它们是同一个式子的三种特化：

$$ h'_v=\sigma\Bigl(\sum_{u\in N(v)}c_{vu}\,W\,h_u\Bigr) $$
  • GCN 把 $c_{vu}$ 固定为 $1/\sqrt{d_v d_u}$（度归一化）。
  • GraphSAGE 把求和换成可学习的 $\mathrm{AGG}$（mean / pool / LSTM），并只对采样到的邻居做。
  • GAT 把 $c_{vu}$ 变成学出来的 $\alpha_{uv}$（注意力）。

所以三者的差别是系数固定、可学，还是与内容相关。
